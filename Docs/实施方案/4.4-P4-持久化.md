# 4.4 P4 - 持久化（L7）

> 目标一句话：刷新页面后对话还在；多标签页历史同步；标题自动生成
> 对应里程碑：M4（2.6 §M4）——可与 P5 的独立设置模块并行，共享入口接线串行
> 设计依据：3.4 §5-§8、3.1 §11、2.5 R12

---

## 0. 实现边界

### 0.1 本阶段必须实现

- 完成 L7 的存储原语、保存编排、跨标签页同步、历史操作和对话标题生成。
- 仅在 L5 做持久化接线：HYDRATE/REHYDRATE、防覆盖、HistoryDropdown 与保存触发，不改变 P3 已冻结的渲染结构。
- 标题生成复用当前活动 Provider，并由 SW 执行 AI SDK `generateText`；Content Script 只经单 Port 发起向后兼容的标题请求。失败时必须走本地标题降级，不能阻塞保存或恢复。

### 0.2 本阶段明确不做

- 不开发或改造正式设置 UI、设置迁移、自定义 origin 权限和连接测试；这些属于 P5。
- 不修改 P2 工具输出、P1 已有 Port 消息变体或 Provider 工厂公共接口。
- 不在 Content Script 直接调用 AI SDK；新增标题消息变体前先回写 3.2 协议，保持单 Port 和已有消息向后兼容。
- 不把 WorkingMemory 与历史记录合并：前者是 5 分钟工具会话状态，后者是长期 ConversationData 快照。
- 不升级 ConversationData 到设计外版本，不加入云同步、导入导出、搜索、分页等未列需求。

### 0.3 与 P5 并行时的文件所有权

- P4 独占 `lib/history/**`、`HistoryDropdown.tsx` 和 ChatContext 的 hydrate/save 逻辑。
- P5 独占设置组件、`settings-migration.ts` 和 manifest 权限；P4 不在这些文件中夹带持久化实现。
- 若双方都需改 `App.tsx`、`styles.ts` 或 `package.json`，按提交顺序窄范围合并，不复制整文件覆盖。

### 0.4 阶段出口与冻结契约

- 刷新恢复、50/200 上限、四类历史操作、标题降级和双标签页同步均通过，P4 才完成。
- 完成后冻结：ConversationData v2、存储 key、syncId 去回声规则、300ms 保存防抖与四个保存触发点。P5 测试可以覆盖这些契约，但不得改写。

### SB-9: 历史 UI + hydrate + 标题生成

```
【任务】移植 src/components/HistoryDropdown.tsx；ChatContext 接通 HYDRATE/REHYDRATE；
        实现标题自动生成（CS 经单 Port 请求，SW 用 AI SDK generateText 替换旧 lightweight-llm 通道）
【设计依据】3.4 §3.4/§8；3.5 §2.3
【硬性契约】

【自测要求】chat-context.test.ts hydration 组用例 + I5/I9/I10 不变量用例
```

## 2. 验收

### 2.1 自动验收

`npm run typecheck && npm run build && npm run test`——history 系列单测全绿。

### 2.2 手动验收（来自 2.6 M4）

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 发送 3 条消息后刷新页面 | 对话完整恢复（含视频/洞察卡） |
| 2 | 打开历史下拉 | 显示 1 条记录 |
| 3 | 对话结束后稍等 | 标题从"新对话"变为 LLM 摘要（≤20字） |
| 4 | 新开标签页 B 新建对话 | 标签页 A 历史下拉自动 +1 |

| 6 | 制造 51 条历史 | 索引截断为 50 |
