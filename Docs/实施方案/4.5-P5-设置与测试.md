## 0. 实现边界

### 0.1 本阶段必须实现

- 用正式四组件替换 P1 临时设置面板，完成内置/自定义 Provider 的新增、编辑、校验、激活与连接测试。
- 完成旧设置迁移和自定义 origin 最小权限申请；权限拒绝不得留下半保存或半激活状态。
- 盘点并补齐既定覆盖矩阵，引入 E2E/CI，执行最终构建、协议关键字清理和发布物验收。
- 主题设置只调用 P3 已冻结的主题引擎，不在设置组件内重复实现同步或 CSS 应用逻辑。

### 0.2 本阶段明确不做

- 不新增 Agent 工具、搜索策略、UI 产品功能或历史能力；测试发现缺陷时只做能证明根因的最小修复。
- 不借“测试收尾”进行目录重构、状态管理替换、依赖大版本升级或 CSS 重写。
- 不改变 P1-P4 已冻结的既有 Port 消息、工具、ChatState 和 ConversationData 契约；连接测试只允许增加向后兼容的消息变体，并先回写 3.2 协议、补完整回归。
- 不把 API Key 安全问题包装为已解决：本阶段只做风险提示、最小权限和错误信息脱敏，不承诺扩展端无法提供的密钥隔离。
- 不在 Content Script 直接调用 AI SDK；连接测试由 UI 经单 Port 发送待测配置，SW 创建临时 model 并执行 10 秒超时的 `generateText("hi")`。

### 0.3 与 P4 并行时的文件所有权

- P5 独占 `components/model-settings/**`、`settings-migration.ts`、Provider 权限申请和 manifest 权限变更。
- P4 独占历史模块和 ChatContext 持久化接线；P5 只为测试增加必要 mock/注入点，不改历史语义。
- E2E 用例应消费稳定的用户界面，不为方便测试添加生产环境后门或专用协议。
- 设置组件和迁移逻辑可与 P4 独立模块并行；SC-4 测试收尾必须等待 P4 阶段提交和共享入口接线完成。

### 0.4 阶段出口与最终冻结

- 设置六项手动验收、全自动门禁、旧协议关键字清零和交付物清单全部通过，P5 才完成。
- 最终冻结：设置迁移兼容规则、origin 授权行为、发布依赖版本和 CI 命令。此后新增能力进入新里程碑，不继续塞入 P5。
