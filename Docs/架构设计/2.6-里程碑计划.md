# 2.6 里程碑计划

## 里程碑依赖关系

```
M0 (L0) ✅
    │
    └──> M1 (L1 + L2 + L3)
            │
            ├──> M2 (L4)
            │      │
            │      └──> M3 (L5 + L6)
            │              │
            │              ├──> M4 (L7)
            │              │
            │              └──> M5 (L8)
            │
            └──> 验证点：能看到流式文本回复
```

**M4 和 M5 可以并行**（历史系统和设置系统互不依赖）

## M1 - 管道打通（L1 + L2 + L3）

### 目标

**一句话**：用户在 bilibili.com 输入"你好"，看到 AI 流式回复"你好！我是 Bilibili 视频搜索助手..."

### 实现内容

#### L1 - 共享基础（最小子集）

| 模块 | 文件 | 说明 |
|------|------|------|
| 类型定义 | `lib/shared-types/index.ts` | ChatMessage、BilibiliVideoCard、ProviderConfig |
| B站客户端 | `lib/bilibili-client/wbi.ts` | WBI 签名（先硬编码测试，后续完善） |
| B站客户端 | `lib/bilibili-client/search.ts` | searchVideo() 函数 |

**暂不实现**：hot / suggest / tags（M2 再做）

#### L2 - 配置与 Provider

| 模块 | 文件 | 说明 |
|------|------|------|
| 设置读写 | `config/settings.ts` | 读写 chrome.storage.local |
| Provider 工厂 | `config/provider-factory.ts` | createModel(config) |
| 内置 Provider | `config/built-in-providers.ts` | 9 个内置 provider 定义 |

**M1 简化**：可以先硬编码一个 OpenAI provider 测试，不用实现完整的设置 UI

#### L3 - 通信管道

| 模块 | 文件 | 说明 |
|------|------|------|
| Port 协议 | `background/port-protocol.ts` | CSMessage / SWMessage 类型定义 |
| streamText | `background/stream.ts` | streamText 调用 + onChunk 推流 |
| SW 入口 | `background/index.ts` | onConnect 监听 + 调用 stream.ts |
| Port 连接 | `content/port-connection.ts` | CS 端 Port 通信 + 消息消费 |
| ChatContext | `content/chat-context.tsx` | 最小状态管理（messages + streamingContent） |

**M1 简化**：
- 工具暂时传空对象 `tools: {}`
- UI 只渲染纯文本，不需要样式
- 不需要历史记录

### 验证标准

**必须通过的测试**：

1. ✅ **构建通过**：`npm run build` 无错误
2. ✅ **扩展加载**：Chrome 能加载 `dist/`
3. ✅ **SW 启动**：chrome://serviceworker-internals 看到 SW 运行
4. ✅ **CS 注入**：bilibili.com 页面控制台无报错
5. ✅ **Port 连接**：CS 能连接到 SW（发送 ping 收到 pong）
6. ✅ **streamText 调用**：SW 里能成功调 `streamText({ model, messages })`
7. ✅ **流式文本**：CS 收到 chunk 消息并实时追加到 UI
8. ✅ **完成消息**：收到 done 消息后 loading 结束

**手动测试步骤**：
```
1. 打开 bilibili.com
2. 看到扩展 UI（即使无样式）
3. 输入"你好"
4. 点击发送
5. 看到"正在思考..."（loading）
6. 看到 AI 回复逐字出现（打字机效果）
7. 回复结束，loading 消失
```

### 风险验证点

## M2 - 工具链完整（L4）

### 目标

**一句话**：输入"yyds 的鬼畜视频"，走完 5 步工作流，返回重排后的视频列表

### 实现内容

#### L4 - 7 个 Agent 工具

| 工具 | 文件 | 说明 |
|------|------|------|
| 黑话理解 | `tools/slang-understand.ts` | 字典匹配 + LLM fallback |
| 查询扩展 | `tools/query-expand.ts` | 调 searchSuggest + searchHot |
| 视频搜索 | `tools/bilibili-search.ts` | 调 searchVideo + WBI 签名 |
| 智能重排 | `tools/video-rerank.ts` | 调 fetchVideoTags + LLM 打分 |
| 澄清引导 | `tools/ask-clarification.ts` | LLM 生成追问 |
| 封面分析 | `tools/analyze-covers.ts` | Vision LLM（可选） |
| 会话记忆 | `tools/working-memory.ts` | chrome.storage.session |

**数据文件**：
- `tools/slang-dictionary.json`（200+ 条）
- `tools/tag-categories.json`（300+ 条）

**L1 补全**：
- `lib/bilibili-client/hot.ts`
- `lib/bilibili-client/suggest.ts`
- `lib/bilibili-client/tags.ts`

**L3 增强**：
- SW 端：`onStepFinish` 推送工具结果
- CS 端：接收 `tool_result` / `videos` / `insight` 消息

### 验证标准

**必须通过的测试**：

1. ✅ **黑话识别**：输入"yyds"，insight 显示"永远的神"
2. ✅ **查询扩展**：生成 keywords / tags / categories
3. ✅ **视频搜索**：返回 BilibiliVideoCard[]
4. ✅ **智能重排**：按相似度重新排序
5. ✅ **工具步骤**：UI 显示 5 个 tool 的执行步骤

**手动测试步骤**：

## 总结

**核心原则**：
1. **依赖驱动**：M1 是关键路径，必须先通管道
2. **渐进增强**：每个里程碑都能独立验证
3. **风险前置**：M1 验证最大风险（AI SDK 兼容性）
4. **并行机会**：M4 和 M5 可以并行（如果有多人）

**关键验证点**：
- M1：能看到流式文本（AI SDK 能跑通）
- M2：能搜索视频（工具链能跑通）
- M3：完整 UI（样式能注入 Shadow DOM）
- M4：历史记录（跨标签页同步）
- M5：全部测试绿（质量保证）
