## 模块间接口定义

### 1. Port 消息协议（L3）

**CS → SW 消息**：

```typescript
// content/port-connection.ts & background/port-protocol.ts

type CSMessage =
  | { type: 'chat'; messages: ChatMessage[]; conversationId: string }
  | { type: 'stop' }
  | { type: 'ping' }

interface ChatMessage {
  role: 'user' | 'assistant' | 'system'
  content: string
  timestamp: number
  toolCalls?: ToolCall[]
}
```

**SW → CS 消息**：

```typescript
type SWMessage =
  | { type: 'chunk'; delta: string }                          // 文本流
  | { type: 'reasoning'; delta: string }                      // 推理流
  | { type: 'tool_start'; toolName: string; args: unknown }   // 工具开始
  | { type: 'tool_result'; toolName: string; result: unknown }// 工具结果
  | { type: 'videos'; videos: BilibiliVideoCard[] }          // 视频列表
  | { type: 'insight'; kind: InsightKind; data: unknown }    // 洞察数据
  | { type: 'done' }                                         // 完成
  | { type: 'error'; message: string; code?: string }        // 错误
  | { type: 'pong' }                                         // 心跳响应

type InsightKind = 'understanding' | 'expansion' | 'rerank' | 'clarification'
```

### 3. 工具接口（L4）

所有工具遵循 AI SDK `tool()` 格式：

```typescript
// tools/*.ts

import { tool } from 'ai'
import { z } from 'zod'

export const slangUnderstand = tool({
  description: '识别网络俚语、缩写、梗文化，标准化为可搜索意图',
  parameters: z.object({
    input: z.string().describe('用户原始输入'),
  }),
  execute: async ({ input }) => {
    // 实现逻辑
    return { original: string, normalized: string, explanation: string }
  },
})
```

**工具返回类型**：

```typescript
// 各工具返回的结构化数据

interface SlangUnderstandResult {
  original: string
  normalized: string
  explanation: string

interface QueryExpandResult {
  keywords: string[]         // <= 8 个
  tags: string[]            // <= 5 个
  categories: string[]      // <= 3 个

}

interface RerankResult {
  items: Array<{
    bvid: string
    score: number           // [0, 1]
  }>
  strategy: string
  trimmed: boolean
}

interface ClarificationRequest {
  question: string
  options?: string[]
  reason: string
}
```

## 模块职责边界

### background/ - Service Worker

**只负责**：
- 监听 Port 连接
- 调用 `streamText`
- 推流给 content script
- 创建 model（调用 L2 provider-factory）

**不负责**：
- UI 渲染
- 用户交互
- DOM 操作

### content/ - Content Script

**只负责**：
- Shadow DOM 挂载
- Port 通信
- React 根节点渲染

**不负责**：
- 业务逻辑（交给 ChatContext）
- LLM 调用（在 SW）

### components/ - UI 组件

**只负责**：
- 渲染 UI
- 用户交互事件
- 样式

**不负责**：
- 数据获取（通过 props 接收）
- Port 通信（通过 context）

### tools/ - Agent 工具

**只负责**：
- 执行单个工具的逻辑
- 返回结构化数据

**不负责**：
- 工具调度（streamText 自动）
- 结果推流（在 SW）

### lib/ - 共享基础

**只负责**：
- 类型定义
- 纯函数（bilibili-client）
- 数据存储（history）

**不负责**：
- UI
- Port 通信

### config/ - 配置

**只负责**：
- 读写 chrome.storage
- 创建 model

**不负责**：
- UI（设置 UI 在 L8）
- 业务逻辑

## 总结

**目录结构特点**：
- 8 个顶层目录对应 8 层架构
- 每层职责清晰，边界明确
- 接口通过 TypeScript 类型定义

**模块间通信**：
- L3 Port 协议：CS ↔ SW 唯一通信方式
- L2 Provider 工厂：统一 model 创建接口
- L4 工具：统一 `tool()` 格式
- L7 历史：统一存储接口

**依赖规则**：
- 下层不依赖上层
- 同层可互相依赖（最小化）
- 跨层通过接口通信
