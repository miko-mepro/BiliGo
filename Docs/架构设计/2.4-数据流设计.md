## 数据生命周期

### 1. 创建阶段

```
用户输入 ──> ChatState.messages
    │
    └──> Port 消息 ──> SW
            │
            └──> streamText
                    │
                    ├──> 工具执行
                    │     └──> 工具结果
                    │
                    └──> LLM 回复
```

### 2. 消费阶段

```
SW 推流 ──> Port 消息 ──> ChatState 更新
                             │
                             └──> React 重渲染
                                    │
                                    └──> 用户看到结果
```

### 3. 持久化阶段

```
ChatState ──> save-orchestrator (防抖 300ms)
                │
                └──> chrome.storage.local
                        │
                        └──> 历史记录
```

### 4. 清理阶段

```
用户关闭面板 ──> 对话保存
    │
    └──> SW 可能被回收（30s 无活动）
            │
            └──> Port 断连
                    │
                    └──> CS 端显示"连接已断开"
```

## 关键数据流路径

### 路径 1：文本流（最简单）

```
LLM 生成文本
  → onChunk({ chunk: { textDelta: "..." } })
  → port.postMessage({ type: 'chunk', delta })
  → dispatch({ type: 'APPEND_STREAMING', delta })
  → streamingContent += delta
  → ChatMessage 打字机渲染
```

### 路径 2：工具流（最复杂）

```
LLM 决定调工具
  → streamText 自动调 tool.execute()
  → onStepFinish({ step: { toolName, toolResult } })
  → port.postMessage({ type: 'tool_result', ... })
  → dispatch({ type: 'ADD_STEP', ... })
  → ChatMessage 显示工具步骤时间线
```

### 路径 3：视频流（特殊）

```
bilibili_search 返回 BilibiliVideoCard[]
  → port.postMessage({ type: 'videos', videos })
  → dispatch({ type: 'SET_VIDEOS', videos })
  → VideoCard[] 渲染
```

### 路径 4：错误流

```
任何错误
  → port.postMessage({ type: 'error', message })
  → dispatch({ type: 'SET_ERROR', error })
  → ErrorDisplay 显示
```

## 总结

**数据流核心**：
1. **单向流**：用户 → CS → SW → LLM → 工具 → SW → CS → UI
2. **流式推送**：SW 不等 LLM 完成，边生成边推流
3. **工具自动化**：streamText 自动执行工具，无需手写循环
4. **状态驱动**：Port 消息 → dispatch → ChatState 更新 → React 渲染

**关键节点**：
- Port 消息协议：CS 和 SW 的唯一通信方式
- streamText：LLM 调用 + 工具执行 + 流式推送的闭环
- ChatState reducer：所有 UI 更新的单一来源
