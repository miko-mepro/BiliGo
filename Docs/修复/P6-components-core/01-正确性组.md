## 发现的问题清单

### 问题 1 · ⑥逻辑错误 · 🔴致命

- **位置**：`src/components/MessageList.tsx:94-96`
- **问题**：auto-scroll useEffect 依赖项遗漏 `state.error`，错误提示出现时不会自动滚动到底部。
- **修复建议**：依赖数组补 `state.error`。

### 问题 2 · ⑥逻辑错误 · 🔴致命

- **位置**：`src/components/HistoryDropdown.tsx:136-145,246-253`
- **问题**：`handleLoad` 加载成功后未关闭下拉，依赖外部 Panel 的 `onLoad` 副作用关闭。组件契约脆弱。
- **修复建议**：在 HistoryDropdown 内部显式处理关闭，或新增 `onRequestClose` prop。

### 问题 3 · ⑥逻辑错误 · 🔴致命

- **位置**：`src/components/ErrorDisplay.tsx:16-19`
- **问题**："重试"按钮与"关闭"按钮功能完全相同。`handleRetry` 仅 `dispatch SET_ERROR null`，没有重新发送消息。用户点重试后什么也没发生。
- **修复建议**：

```tsx
const { dispatch, state, sendMessage } = useChat()
const lastUserMsg = [...state.messages].reverse().find(m => m.role === 'user')
const handleRetry = useCallback((): void => {
  if (!lastUserMsg) { dispatch({ type: 'SET_ERROR', payload: null }); return }
  dispatch({ type: 'SET_ERROR', payload: null })
  void sendMessage(lastUserMsg.content)
}, [dispatch, lastUserMsg, sendMessage])
```

### 问题 4 · ⑥逻辑错误 · 🟡警告

### 问题 5 · ⑤空指针 · 🟠严重

- **位置**：`src/components/HistoryDropdown.tsx:280`
- **问题**：onBlur 触发 handleRenameConfirm 时，若条目被 sync 远程删除，editing.id 已不在 records 中但仍发 onRename 请求。
- **修复建议**：handleRenameConfirm 前 check records 中是否还含此 id。

### 问题 6 · ②类型错误 · 🟠严重

- **位置**：`src/components/ErrorDisplay.tsx:21-24`
- **问题**：`error.code` 类型比较混用 `String(error.code) === '429'` 和 `error.code === '401'`。
- **修复建议**：统一用 `String(error.code)` 或定义 `ERROR_CODES` 常量。

### 问题 7 · ⑤空指针 · 🟡警告
