## 发现的问题清单

### 维度 ⑨ - 安全漏洞

#### 问题 1 · ⑨ · 🟠严重

- **位置**：`src/lib/bilibili-client/search.ts:120` / `src/lib/bilibili-client/tags.ts:82`
- **问题**：`headers.Cookie = 'SESSDATA=' + sessdata` 直接字符串拼接。若 `sessdata` 含 `; `、`\n` 或 `\r` 等特殊字符，可注入额外 cookie 字段。代码无校验。同时 Chrome 扩展 SW 中手动设置 Cookie header 会覆盖扩展默认通过 `credentials: "include"` 自动携带的 cookie。
- **修复建议**：

```ts
const SESSDATA_PATTERN = /^[A-Za-z0-9_%-]+$/

function buildHeaders(sessdata: string | undefined): HeadersInit {
  const headers: Record<string, string> = { Accept: 'application/json' }
  if (sessdata) {
    if (!SESSDATA_PATTERN.test(sessdata)) {
      throw new BilibiliApiError('Invalid SESSDATA format')
    }
    headers.Cookie = `SESSDATA=${sessdata}`
  }
  return headers
}
```

#### 问题 2 · ⑨ · 🟡警告

- **位置**：`src/lib/bilibili-client/search.ts:98-99`
- **问题**：`credentials: "include"` 与手动 Cookie header 并存。手动 Cookie header 会覆盖自动携带的 cookie，导致扩展用户已登录的 B 站身份信息丢失。
- **修复建议**：二选一：方案 A 仅用 `credentials: "include"`（推荐）；方案 B 仅用手动 Cookie（隔离扩展身份）。

#### 问题 3 · ⑨ · 🟡警告

- **位置**：`src/lib/bilibili-client/search.ts:75` / `hot.ts:40` / `tags.ts:47`
- **问题**：`response.json()` 返回 null 时后续访问崩溃。`.catch` 只捕获 JSON 解析错误，不捕获后续属性访问错误。
- **修复建议**：增加 null 检查：

```ts
const body = (await response.json().catch(...)) as BilibiliSearchResponse | null
if (!body || typeof body !== 'object') {
  throw new BilibiliApiError('Bilibili search response is not a valid object')
}
```

#### 问题 4 · ⑨ · 🔵建议

- **位置**：`src/lib/bilibili-client/suggest.ts:23`
- **问题**：错误消息可能暴露用户输入。当前未泄露但需注意。
- **修复建议**：保持现状，但未来扩展错误消息勿拼接原始 term。

### 维度 ⑪ - 配置/环境问题

#### 问题 5 · ⑪ · 🟡警告

- **位置**：`src/lib/bilibili-client/suggest.ts:27`
- **问题**：手动拼接 query string `url.search = 'term=' + encodeURIComponent(term) + '&main_ver=v1'`，与其他文件使用 `url.searchParams.set()` 风格不一致。
- **修复建议**：

```ts
const url = new URL(SUGGEST_URL)
url.searchParams.set('term', term)
url.searchParams.set('main_ver', 'v1')
```

#### 问题 6 · ⑪ · 🟡警告

- **位置**：`src/lib/bilibili-client/hot.ts:25`
- **问题**：`searchHot(limit: number = 20)` 直接 `String(limit)` 拼接到 URL，无输入校验。负数、0、NaN 或超大值可能引发异常。
- **修复建议**：增加范围校验：

```ts
if (!Number.isFinite(limit) || limit < 1) limit = 20
else if (limit > 100) limit = 100
```

#### 问题 7 · ⑪ · 🔵建议

- **位置**：所有文件
- **问题**：HOT_URL、SEARCH_URL、SUGGEST_URL、TAGS_URL、NAV_URL 分散在 5 个文件中。
- **修复建议**：集中到 `endpoints.ts` 配置文件。

#### 问题 8 · ⑪ · 🔵建议

- **位置**：`src/lib/bilibili-client/wbi.ts:2`
- **问题**：`WBI_KEY_TTL_MS = 6 小时` 偏保守，B 站 WBI key 实际有效期较长。
- **修复建议**：可适当延长至 12 小时。

## 审计总结

- **WBI 签名算法**（wbi.ts）：MIXIN_KEY_ENC_TAB、md5 实现、buildSigningQuery 排序+过滤、wts 时间戳、w_rid 计算均符合 B 站 WBI 标准规范，实现正确。
- **错误处理**：BilibiliRiskError(-352)、BilibiliNetworkError、BilibiliApiError 三层错误体系清晰。
- **类型安全**：所有 `unknown` 类型字段均通过 `toStringValue`/`toNumber` 守卫转换，无直接 `as` 强制断言风险。
- **主要风险点**：Cookie 拼接注入风险（🟠）和 credentials 冲突（🟡）是需优先处理的安全问题，建议在合并前修复 ⑨🟠 项。
