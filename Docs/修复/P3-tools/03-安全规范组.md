### 维度 ⑨ - 安全漏洞

#### 问题 4 · ⑨ · 🟡警告

- **位置**：`src/tools/analyze-covers.ts:196-208`
- **问题**：`fetchCoverAsDataUrl` 未验证 picUrl 协议白名单。若 picUrl 为 `file:///etc/passwd`、`data:text/html,...` 或内网地址，会被 fetch 直接请求，存在 SSRF 风险。
- **修复建议**：

```ts
async function fetchCoverAsDataUrl(
  picUrl: string,
  fetchImpl: typeof fetch,
): Promise<string> {
  const normalizedUrl = normalizePicUrl(picUrl)
  if (!isAllowedCoverUrl(normalizedUrl)) {
    throw new Error(`Blocked disallowed cover URL protocol`)
  }
  const response = await fetchImpl(normalizedUrl)
  // ... 后续不变
}

function isAllowedCoverUrl(url: string): boolean {
  try {
    const parsed = new URL(url)
    return parsed.protocol === 'http:' || parsed.protocol === 'https:'
  } catch {
    return false
  }
}
```

#### 问题 5 · ⑨ · 🟡警告

- **位置**：`src/tools/slang-understand.ts:189-201`
- **问题**：`safeUpdateMemory` 注释说"追加"但实际是"覆盖"。`memoryStore.update({ triedKeywords: [normalized] })` 会整体替换现有数组。
- **修复建议**：改为先读后追加：

```ts
async function safeUpdateMemory(
  memoryStore: UnderstandMemoryStore,
  normalized: string,
): Promise<void> {
  if (!normalized || normalized.trim().length === 0) return
  try {
    const existing = await memoryStore.get()
    const existingKeywords = existing?.triedKeywords ?? []
    await memoryStore.update({
      triedKeywords: [...existingKeywords, normalized],
    })
  } catch {
    // memoryStore 写入失败不影响工具返回
  }
}
```

### 维度 ⑪ - 配置/环境问题

#### 问题 7 · ⑪ · 🟡警告

- **位置**：`src/tools/llm-json.ts:117-155`
- **问题**：`tryGenerateObject` 和 `tryGenerateText` 均未设置 `abortSignal`。若 LLM provider 响应慢或卡住，调用会永久阻塞。
- **修复建议**：添加 30s 超时：

```ts
const result = await generateObject({
  model, schema, messages,
  ...(system ? { system } : {}),
  abortSignal: AbortSignal.timeout(30_000),
})
```

#### 问题 8 · ⑪ · 🟡警告

- **位置**：`src/tools/video-rerank.ts:92-107`
- **问题**：`Promise.allSettled` 对 30 个视频并发 `fetchVideoTags`，无并发限制。30 路同时请求 B 站 tag API 极易触发 -352 风控或 IP 限流。
- **修复建议**：分批并发，每批 5 个。

#### 问题 9 · ⑪ · 🟡警告

- **位置**：`src/tools/llm-json.ts:96-105`
- **问题**：`splitSystemMessage` 只取第一个 system 消息，`filter((m) => m.role !== 'system')` 会丢弃所有 system 消息。若调用方传入多条 system 消息，第 2 条及之后会被静默丢弃。
- **修复建议**：合并所有 system 消息：

```ts
function splitSystemMessage(messages: ChatMessage[]) {
  const systemMessages = messages.filter((m) => m.role === 'system')
  if (systemMessages.length === 0) return { system: undefined, rest: messages }
  const system = systemMessages.map((m) => m.content).join('\n\n')
  return { system, rest: messages.filter((m) => m.role !== 'system') }
}
```
