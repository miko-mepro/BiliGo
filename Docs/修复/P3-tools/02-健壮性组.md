### 问题 3 · ⑦并发/资源泄漏 · 🟠严重

- **位置**：`src/tools/working-memory.ts:43-57`
- **问题**：`update` 方法先 `await this.get(traceId)` 再 `await chrome.storage.session.set(...)`，两步之间非原子操作。并发 `update` 时后写覆盖先写（lost update）。`ask-clarification.ts:61-63` 的 clarificationCount 递增正是受影响场景。
- **修复建议**：使用版本号乐观锁，或在 update 内部加 retry；或在 SC-1 编排层保证同一 traceId 的工具调用串行：

```ts
static async updateWithRetry(
  traceId: string,
  patch: Partial<WorkingMemory>,
  maxRetries = 3,
): Promise<WorkingMemory | undefined> {
  const key = STORAGE_PREFIX + traceId
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const result = await chrome.storage.session.get(key)
    const stored = result[key] as StoredEntry | undefined
    if (!stored) return undefined
    if (Date.now() > stored.expiresAt) {
      await chrome.storage.session.remove(key)
      return undefined
    }
    const updated: WorkingMemory = { ...stored.data, ...patch, traceId }
    await chrome.storage.session.set({
      [key]: { data: updated, expiresAt: Date.now() + TTL_MS },
    })
    return updated
  }
  return undefined
}
```

```ts
  safeCall(async () => {

    return searchSuggest(seed[0])
  }),
  safeCall(() => searchHot(HOT_LIMIT)),
])
```
