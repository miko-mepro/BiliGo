## 发现的问题清单

### 问题 1 · ⑥逻辑错误 · 🟡警告

- **位置**：`src/tools/slang-understand.ts:195-197`
- **问题**：`safeUpdateMemory` 调用 `memoryStore.update({ triedKeywords: [normalized] })`，而 `WorkingMemoryStore.update`（working-memory.ts:50）实现是浅合并 `{ ...existing, ...patch, traceId }`，导致 `patch.triedKeywords` 完全替换 `existing.triedKeywords`，丢失之前所有已记录的关键词。注释（line 186-188）声称"追加"但实际是"覆盖"。对比 `query-expand.ts:221-233` 的 `recordToMemory` 正确实现了读取-合并-去重-写入。
- **影响场景**：若 `slang_understand` 在其他工具之后被调用，会清空 `query_expand` 等工具之前累积的 triedKeywords，导致 WorkingMemory 状态丢失。
- **修复建议**：

```ts
async function safeUpdateMemory(
  memoryStore: UnderstandMemoryStore,
  normalized: string,
): Promise<void> {
  if (!normalized || normalized.trim().length === 0) return
  try {
    const existing = await memoryStore.get()
    const merged = existing
      ? Array.from(new Set([...existing.triedKeywords, normalized]))
      : [normalized]
    await memoryStore.update({
      triedKeywords: merged,
    })
  } catch {
    // memoryStore 写入失败不影响工具返回
  }
}
```

### 问题 3 · ②类型错误 · 🔵建议

- **位置**：`src/tools/video-rerank.ts:46,83`
- **问题**：`defaultCallLlmForJson as unknown as LlmJsonCaller` 双重断言。
- **修复建议**：显式包装适配器：

```ts
const callLlm: LlmJsonCaller = deps.callLlmForJson ?? (async (messages) => {

```

### 问题 4 · ②类型错误 · 🔵建议

- **位置**：`src/tools/llm-json.ts:48`
- **问题**：`(parsed as T | null) ?? null` 中，`??` 仅对 null/undefined 生效。若 LLM 返回 `"0"`/`"false"`，parseJsonFromText 解析为 `0`/`false`，不会被转为 null。
- **修复建议**：调用方均有结构化字段检查兜底，实际不会触发问题。保持现状。
