## 发现的问题清单

### 问题 1 · ⑥逻辑错误 · 🔴致命

- **位置**：`src/content/chat-context.tsx:686`
- **问题**：`titleRequestedRef.current.add(current.conversationId)` 在第 688 行 `if (connection && !connection.isDisconnected())` 检查**之前**执行。如果保存对话时连接恰好断开，conversationId 会被记录为"已请求标题"，但 `generate_title` 消息从未发送，兜底定时器也从未启动。连接恢复后再次保存对话时，由于 `titleRequestedRef` 已有记录，不会重试。结果是该会话标题永远是临时标题，且 `titleFinal` 永不为 true。
- **修复建议**：将 `add` 调用移到连接可用判断块内：

```tsx
// chat-context.tsx:684 附近
if (
  messages.length >= 2 &&
  !titleRequestedRef.current.has(current.conversationId)
) {
  const connection = connectionRef.current
  if (connection && !connection.isDisconnected()) {
    // 仅在实际发送 generate_title 时才记录
    titleRequestedRef.current.add(current.conversationId)
    connection.postMessage({
      type: 'generate_title',
      conversationId: current.conversationId,
      messages: messages.slice(0, 2),
    })
    const convIdForTitle = current.conversationId
    const fallbackTimer = setTimeout(() => {
      // ... 兜底逻辑不变
    }, TITLE_FALLBACK_TIMEOUT_MS)
    titleTimeoutsRef.current.set(convIdForTitle, fallbackTimer)
  }
}
```

### 问题 2 · ⑥逻辑错误 · 🟠严重

- **位置**：`src/content/chat-context.tsx:503`
- **问题**：`if (msg.conversationId === currentConv)` 检查当前会话是否匹配。如果用户在 SW 生成标题期间切换了会话，SW 返回的 title 消息的 conversationId 与当前会话不匹配，标题不会写入历史记录。兜底定时器虽然会清除，但标题更新被跳过，导致旧会话标题可能永久为临时标题。
- **修复建议**：无论 conversationId 是否匹配当前会话，都应更新历史记录中的标题：

```tsx
case 'title': {
  // 无论当前会话是否匹配，都应更新历史记录中的标题
  void (async () => {
    try {
      await updateTitle(msg.conversationId, msg.title)
      window.dispatchEvent(new Event(HISTORY_INDEX_DIRTY_EVENT))
    } catch {
      // 标题更新失败不阻塞聊天
    }
  })()
  break
}
```

### 问题 3 · ⑥逻辑错误 · 🟡警告

- **位置**：`src/content/chat-context.tsx:462-469`
- **问题**：`const current = stateRef.current` 读取的 `streamingContent` 来自 stateRef，而 stateRef 在 `useEffect [state]`（第 550-555 行）中同步。如果 chunk 消息和 done 消息在同一个事件循环 tick 中被批量处理，dispatch APPEND_STREAMING 产生的 state 更新尚未触发 useEffect，stateRef.current.streamingContent 不包含最后几个 chunk 的 delta，导致 `UPDATE_LAST_MESSAGE` 写入的 content 不完整。
- **修复建议**：在 consumeSWMessage 的 chunk 分支中同步更新 stateRef.current.streamingContent：

```tsx
case 'chunk':
  ensureAssistantPlaceholder(stateRef, dispatch)
  dispatch({ type: 'APPEND_STREAMING', payload: msg.delta })
  // 同步更新 ref，避免 done 消息在 useEffect 执行前读取到旧值
  stateRef.current = {
    ...stateRef.current,
    streamingContent: stateRef.current.streamingContent + msg.delta,
  }
  break
```

同理，reasoning 分支（第 400-403 行）也应同步更新 `streamingReasoning`。

### 问题 4 · ②类型错误 · ⚠️警告

- **位置**：`src/content/chat-context.tsx:135,383,473,603,772`
- **问题**：`ConsumerStateRef = RefObject<ConsumerState>` 在 React 18 的 @types/react 中，`RefObject<T>.current` 为 `readonly T | null`。但 `ensureAssistantPlaceholder`（第 383 行）、`consumeSWMessage` done 分支（第 473 行）、onDisconnect 回调（第 603 行）、REHYDRATE 回调（第 772 行）均对 `stateRef.current` 直接赋值。代码能运行说明项目可能使用 React 19 @types/react 或 tsconfig 配置宽松。
- **修复建议**：改为 `MutableRefObject` 以明确可变意图：

```tsx
import { type MutableRefObject } from 'react'

export type ConsumerStateRef = MutableRefObject<ConsumerState>
```

### 问题 5 · ⑥逻辑错误 · 🟡警告

- **位置**：`src/content/port-connection.ts:90-93`
- **问题**：仅在收到 `pong` 消息时调用 `resetPongTimer()`。如果 SW 正在处理长时间的 AI 生成并持续发送 chunk/tool_start 等消息但未及时响应 ping，pong 超时（60s）会触发 `fireDisconnect()`，导致正在进行的对话被中断。
- **修复建议**：在收到任何 SW 消息时重置 pong 超时：

```ts
const messageListener = (msg: unknown): void => {
  if (!isSWMessage(msg)) return
  // 任何消息都说明连接活跃，重置 pong 超时
  resetPongTimer()
  if (msg.type === 'pong') {
    return
  }
  for (const handler of messageHandlers) {
    handler(msg)
  }
}
```
