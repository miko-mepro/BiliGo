## 发现的问题清单

### 维度 ⑦ - 并发/资源泄漏

#### 问题 1 · ⑦ · 🔴致命

- **位置**：`src/content/index.tsx:67-81`
- **问题**：`MutationObserver` 在 `startObserver()` 中创建后**永不 disconnect**。content script 在 SPA 路由切换时可能被多次注入，每次 `startObserver` 虽然先 `observer.disconnect()` 旧实例，但全局 `observer` 变量被覆盖；若脚本被重新注入，旧 observer 会泄漏且继续观察已脱离文档的节点。
- **修复建议**：

```tsx
function startObserver(): void {
  if (observer) observer.disconnect()
  observer = new MutationObserver(/* ... */)
  observer.observe(document.documentElement, { childList: true, subtree: false })
  if (document.body) observer.observe(document.body, { childList: true, subtree: false })
}

// 新增 pagehide 清理
window.addEventListener('pagehide', () => {
  observer?.disconnect()
  observer = null
  mountedRoot?.unmount()
  mountedHost?.remove()
}, { once: true })
```

#### 问题 2 · ⑦ · 🟠严重

- **位置**：`src/content/chat-context.tsx:541,548,684`
- **问题**：`titleRequestedRef`（Set）和 `titleTimeoutsRef`（Map）在整个 Provider 生命周期内只增不减。用户长期使用后累积所有历史 conversationId。`clearChat()`（第 845 行）不重置 `titleRequestedRef`，若用户在同一会话内清空后重新发送，会因 Set 已含该 id 而跳过标题请求。
- **修复建议**：

```tsx
const clearChat = (): void => {
  void clearLocalCache()
  const convId = stateRef.current.conversationId
  titleRequestedRef.current.delete(convId)
  const t = titleTimeoutsRef.current.get(convId)
  if (t) {
    clearTimeout(t)
    titleTimeoutsRef.current.delete(convId)
  }
  dispatch({ type: 'CLEAR_MESSAGES' })
}
```

#### 问题 3 · ⑦ · 🟡警告

- **位置**：`src/content/chat-context.tsx:825-827`
- **问题**：`send()` 中构造 `committedMessages` 时用 `[...stateRef.current.messages, userMessage]` 拼接，但 `userMessage` 已在第 815 行通过 `ADD_MESSAGE` dispatch 加入 state。`stateRef.current.messages` 在 dispatch 后未必已同步更新，若 ref 尚未更新，`committedMessages` 会缺失 userMessage；若已更新，会重复包含。
- **修复建议**：

```tsx
const userMessage = { role: 'user', content: trimmed, timestamp: Date.now() }
const committedMessages = [
  ...stateRef.current.messages.filter(m => m.role !== 'assistant' || m.content || m.steps?.length),
  userMessage
]
dispatch({ type: 'ADD_MESSAGE', payload: userMessage })
```

#### 问题 4 · ⑦ · 🔵建议

- **位置**：`src/content/port-connection.ts:40-41`
- **问题**：`connectionRef.current = connectChatPort(handlers)`（第 611 行）覆盖旧 connection 时，旧 connection 的 `disconnect()` 未被调用。
- **修复建议**：

```tsx
const connect = (): void => {
  connectionRef.current?.disconnect()

  connectionRef.current = connectChatPort(handlers)

```

### 维度 ⑧ - 性能问题

#### 问题 5 · ⑧ · 🟡警告

- **位置**：`src/content/chat-context.tsx:180-184`
- **问题**：`APPEND_STREAMING`/`APPEND_REASONING` 用 `state.streamingContent + action.payload` 字符串拼接。长回答下每次 chunk 触发 O(n) 字符串拷贝。
- **修复建议**：短期可接受；若优化可将 streaming 文本存入 ref + 直接 DOM 写入，绕过 React 渲染。

#### 问题 6 · ⑧ · 🟡警告

- **位置**：`src/content/index.tsx:69-71`
- **问题**：`MutationObserver` 回调直接调 `ensureMounted()`，未防抖。B 站 SPA 路由切换时会触发高频 DOM 变更。
- **修复建议**：

```tsx
let rafId: number | null = null
observer = new MutationObserver(() => {
  if (rafId !== null) return
  rafId = requestAnimationFrame(() => {
    rafId = null
    ensureMounted()
  })
})
```

#### 问题 7 · ⑧ · 🔵建议

- **位置**：`src/content/chat-context.tsx:851-860`
- **问题**：`useChatController` 返回的对象每次渲染都是新对象字面量，`send`/`stop`/`clearChat` 未用 `useCallback` 包裹。

```tsx
const send = useCallback((text: string) => { /* ... */ }, [])
const stop = useCallback(() => { connectionRef.current?.postMessage({ type: 'stop' }) }, [])
const clearChat = useCallback(() => { /* ... */ }, [])
return useMemo(() => ({ state, dispatch, send, stop, sendMessage: send, stopGeneration: stop, clearChat, connection: connectionRef.current }), [state, send, stop, clearChat])
```

### 维度 ⑩ - 错误处理缺失

#### 问题 8 · ⑩ · 🟠严重

- **位置**：`src/content/error-boundary.tsx:23-25`
- **问题**：`componentDidCatch` 仅 `console.error`，未上报到 SW 或任何监控通道。`getDerivedStateFromError` 只存 `error.message`，丢失了 stack trace。
- **修复建议**：

```tsx
interface ErrorBoundaryState {
  hasError: boolean
  message: string
  stack?: string
}

static getDerivedStateFromError(error: Error): ErrorBoundaryState {
  return { hasError: true, message: error.message ?? '未知错误', stack: error.stack }
}

componentDidCatch(error: Error, info: ErrorInfo): void {
  console.error('[BiliAgent] ErrorBoundary caught:', error, info)
  try {
    chrome.runtime?.sendMessage({
      type: 'content_error',
      message: error.message,
      stack: error.stack,
      componentStack: info.componentStack
    })
  } catch { /* SW 不可用 */ }
}
```

} catch (e) {
