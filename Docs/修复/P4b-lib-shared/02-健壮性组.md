## 发现的问题清单

### 问题 1 · ⑦并发/资源泄漏 · 🟠严重

- **位置**：`src/lib/history/save-orchestrator.ts:262-281`
- **问题**：触发点5（isLoading 转换）的 useEffect 没有 cleanup 函数。组件卸载时若 `saveCurrentConversation()` 进行中，完成后仍调用 `callbacks.dispatchHistoryIndexDirty()`。与触发点4（行222-253）使用 `cancelled` 标志保护形成不一致。
- **修复建议**：

```ts
useEffect(() => {
  if (!hydrated) { wasLoadingRef.current = state.isLoading; return }
  const wasLoading = wasLoadingRef.current
  wasLoadingRef.current = state.isLoading
  if (!(wasLoading && !state.isLoading)) return
  if (!hasAiActivity(state)) return
  let cancelled = false
  void (async () => {
    try {
      await callbacks.saveCurrentConversation()
      if (!cancelled) callbacks.dispatchHistoryIndexDirty()
    } catch {}
  })()
  return () => { cancelled = true }
}, [hydrated, state, callbacks])
```

### 问题 2 · ⑦并发/资源泄漏 · 🟡警告

- **位置**：`src/lib/history/sync.ts:87-89`
- **问题**：`trackedWrite` 中的 `setTimeout` 未在 `stop()` 中清理。大量未清理的定时器在频繁写入时累积。
- **修复建议**：维护一个 `timeoutIds: Set`，在 `stop()` 中全部 `clearTimeout`。

### 问题 3 · ⑦并发/资源泄漏 · 🟡警告

- **位置**：`src/lib/history/store.ts:81-134`
- **问题**：`saveConversation` 是非原子的 read-modify-write。两个标签页并发保存不同 conversationId 时，后写入者会覆盖前者的索引更新。
- **修复建议**：短期可接受（chrome.storage 无锁原语）；长期考虑用 `navigator.locks` API 或单标签页写入策略。

### 问题 4 · ⑧性能问题 · 🟠严重

- **位置**：`src/lib/shared-types/sanitize.ts:12-36`
- **问题**：`sanitize` 递归遍历对象无深度限制。若输入含循环引用（如 `a.self = a`），会无限递归导致栈溢出崩溃。
- **修复建议**：

```ts
export function sanitize(obj: unknown, seen?: WeakSet<object>): unknown {
  if (obj === null || obj === undefined) return obj
  if (typeof obj !== 'object') return obj
  if (Array.isArray(obj)) return obj.map((v) => sanitize(v, seen))
  const objRecord = obj as Record<string, unknown>
  seen = seen ?? new WeakSet()
  if (seen.has(objRecord)) return '[CIRCULAR]'
  seen.add(objRecord)
  const result: Record<string, unknown> = {}
  for (const [key, value] of Object.entries(objRecord)) {
    const lowerKey = key.toLowerCase()
    if (SENSITIVE_KEYS.includes(lowerKey)) { result[key] = '[REDACTED]' }
    else if (typeof value === 'object' && value !== null) { result[key] = sanitize(value, seen) }
    else { result[key] = value }
  }
  return result
}
```

### 问题 5 · ⑧性能问题 · 🔵建议

- **位置**：`src/lib/shared-types/sanitize.ts:1-10`
- **问题**：`SENSITIVE_KEYS` 是数组，`includes` 为 O(n)。
- **修复建议**：改为 `Set`，`SENSITIVE_KEYS.has(lowerKey)`。
