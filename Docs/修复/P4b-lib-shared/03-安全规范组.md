## 发现的问题清单

### 问题 1 · ⑨安全漏洞 · 🟠严重

- **位置**：`src/lib/shared-types/sanitize.ts:1-10`
- **问题**：`SENSITIVE_KEYS` 列表不完整。本项目 `ProviderConfig` 含 `apiKey` 字段，但 `apiKey` 小写为 `apikey`，不在列表中。该函数作为公共导出的脱敏函数，若用于日志脱敏包含 `ProviderConfig` 的对象，`apiKey` 会被明文输出，造成敏感信息泄露。
- **修复建议**：

```ts
const SENSITIVE_KEYS = [
  'cookie', 'authorization', 'sessdata', 'set-cookie',
  'x-install-id', 'install-id', 'installid', 'x-openrouter-api-key',
  // 新增：覆盖本项目及业界常见敏感字段
  'apikey', 'api-key', 'api_key', 'x-api-key',
  'token', 'access-token', 'access_token', 'accesstoken',
  'secret', 'password', 'passwd', 'credential', 'credentials',
]
```

### 问题 2 · ⑪配置/环境问题 · 🟡警告

- **位置**：`src/lib/history/save-orchestrator.ts:35,37` 与 `src/lib/history/store.ts:22,18`
- **问题**：`MAX_PERSISTED_MESSAGES` 和 `CONVERSATION_STORAGE_KEY` 在两个文件中各自独立定义。`store.ts:22` 已 `export const MAX_PERSISTED_MESSAGES`，但 `save-orchestrator.ts` 未导入而是重新声明。`store.ts:18` 的 `CONVERSATION_STORAGE_KEY` 未 export。
- **修复建议**：在 `store.ts` 中 export `CONVERSATION_STORAGE_KEY`，在 `save-orchestrator.ts` 中删除本地声明改为导入。

### 问题 3 · ⑨安全漏洞 · 🟡警告

- **位置**：`src/lib/history/store.ts:59-66,139-153` + `src/lib/history/sync.ts:52-55`
- **问题**：从 `chrome.storage.local` 读取的数据直接用 `as` 类型断言，未校验元素结构。`getHistoryIndex` 仅检查 `Array.isArray(value)`，不校验数组元素是否为合法 `ConversationRecord`。
- **修复建议**：

```ts
return value.filter(
  (r): r is ConversationRecord =>
    r !== null && typeof r === 'object' &&
    typeof r.id === 'string' && typeof r.title === 'string' &&
    typeof r.createdAt === 'number',
)
```

### 问题 4 · ④导入/引用错误 · 🔵建议

- **位置**：`src/lib/history/store.ts:13` vs `src/lib/history/save-orchestrator.ts:23`
- **问题**：两个文件位于同一目录，导入 `shared-types/index.js` 的路径风格不一致：`'../shared-types/index.js'` vs `'../../lib/shared-types/index.js'`。
- **修复建议**：统一为简短相对路径 `'../shared-types/index.js'`。

### 问题 5 · ④导入/引用错误 · 🔵建议

- **位置**：`src/lib/history/save-orchestrator.ts:106-116`
- **问题**：`PersistedConversationCache` 接口与 `store.ts:29-38` 的 `PersistedConversation` 完全同构，注释声称"避免循环依赖"，但 `save-orchestrator.ts` 已从 `store.js` 导入值，不存在循环依赖。
- **修复建议**：直接从 `store.ts` 导入类型，删除重复声明。

### 问题 6 · ⑨安全漏洞 · 🔵建议

- **位置**：`src/lib/history/save-orchestrator.ts:132-134,246-248,277-279`
- **问题**：三处 `catch {}` 静默吞掉所有异常，无任何日志记录。
- **修复建议**：添加 `console.warn` 记录错误。
