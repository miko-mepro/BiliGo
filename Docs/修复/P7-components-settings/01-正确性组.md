## 发现的问题清单

### 问题 1 · ⑥逻辑错误 · 🔴致命

- **位置**：`src/components/model-settings/SettingsPanel.tsx:185-221`
- **问题**：`chrome.permissions.request` 在 for...of 循环中逐个 await，第二个起脱离用户手势上下文。Chrome MV3 要求 `chrome.permissions.request` 必须在用户手势栈内调用。多自定义 provider 场景下第二个起永远保存失败。
- **修复建议**：先同步遍历收集所有非内置 origin pattern，再一次性批量请求：

```tsx
const pendingPatterns: string[] = []
for (const provider of providers) {
  if (!provider.isCustom) continue
  const baseUrl = provider.baseUrl
  if (baseUrl.trim() === "") continue
  if (isBuiltInProviderOrigin(baseUrl)) continue
  const pattern = resolveOriginPattern(baseUrl)
  if (pattern === "") continue
  pendingPatterns.push(pattern)
}
if (pendingPatterns.length > 0) {
  const granted = await chrome.permissions.request({ origins: pendingPatterns })
  if (!granted) { setSaveError("需要授权访问该域名"); setSaveStatus("error"); return }
}
```

### 问题 2 · ⑥逻辑错误 · 🟠严重

- **位置**：`src/components/model-settings/SettingsPanel.tsx:399,432-443`
- **问题**：ProviderForm 校验状态从未被消费。`handleSave` 从未读取 ProviderForm 的校验状态，直接保存。用户可保存 name=""、apiKey=""、model="" 的无效 provider。
- **修复建议**：在 handleSave 顶部对 providers 做完整性校验。

### 问题 3 · ⑥逻辑错误 · 🟠严重

- **位置**：`src/components/model-settings/TestConnectionButton.tsx:153`
- **问题**：`port.postMessage` 未 try/catch，Port 断开时抛异常未处理。按钮卡在 testing 态。
- **修复建议**：

```tsx
try {
  port.postMessage({ type: "test_connection", provider })
} catch {
  setStatus("fail")
  setErrorMessage("连接通道已断开")
  cleanup()
  return
}
```

### 问题 5 · ⑥逻辑错误 · 🟡警告
