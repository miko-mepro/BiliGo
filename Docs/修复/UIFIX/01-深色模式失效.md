# UIFIX-01 · 深色模式切换 UI 不变色

> 发现日期：2026-07-30
> 严重程度：🔴 致命（功能完全失效，用户可感知）
> 影响范围：整个面板 UI（70+ 处硬编码颜色，全部无法响应深色模式）
> 修复优先级：P0（阻断"深色模式"功能交付）

---

## 一、问题现象

用户在「设置 → 外观 → 主题模式」选择 **dark（强制深色）** 并保存后：

- ❌ 面板背景仍为白色（`#FFFFFF`）
- ❌ 所有卡片、输入框、消息气泡颜色不变
- ❌ 文字仍为近黑色（`#18191C`），在深色背景需求下完全无变化
- ✅ settings.themeMode 确实已持久化为 `dark`（storage 写入正常）
- ✅ useTheme hook 返回值正确为 `'dark'`（state 解析正常）
- ✅ 根节点 DOM 上 `bili-agent-theme-dark` class 与 `data-theme="dark"` 属性已正确添加

**结论**：状态链路全通，唯独"最后一步 CSS 渲染"完全缺失。

| ⑧ **CSS 深色规则定义** | `content/styles.ts` | ❌ **完全缺失** | 1792 行 CSS 中 0 处 `.bili-agent-theme-dark` / `[data-theme="dark"]` 选择器 |

### 2.2 根因（致命）

**`Main/src/content/styles.ts`（共 1792 行）完全没有实现深色模式的 CSS。**

- 全部 70+ 处颜色值为硬编码浅色：
  - `#FFFFFF`（白色背景，出现 20+ 次）
  - `#F4F5F7`、`#FAFBFC`、`#F8F9FA`、`#F6F7F8`（浅灰背景）
  - `#FFF5F7`、`#FFF7E6`、`#FFF1F0`（浅色卡片头）
  - `#18191C`（主文字近黑）、`#61666D`、`#9499A0`（次要文字灰）
- **没有任何 CSS 变量**（`--xxx`）定义
- **没有任何深色作用域选择器**：
  - `.bili-agent-theme-dark { ... }` —— 0 处
  - `[data-theme="dark"] { ... }` —— 0 处
  - `.bili-agent-theme-dark .xxx { ... }` —— 0 处
  - `@media (prefers-color-scheme: dark) { ... }` —— 0 处（auto 模式也无 fallback）

### 2.3 设计文档与实现的背离

设计文档 `Docs/详细设计/3.5-UI线框图.md:443-451` 明确承诺：

```
| 模式 | 说明 | 实现 |
|------|------|------|
| auto | 跟随系统 | 监听 prefers-color-scheme |
| light | 强制浅色 | - |
| dark | 强制深色 | CSS 变量覆盖 |   ← 承诺用 CSS 变量，实际未实现
```

设计文档 `Docs/实施方案/4.3-P3-UI完整.md:148` 验收标准：

```
| 7 | 切换深色模式 | 全 UI 变色；另一标签页同步 |
```

实际实现：状态同步了，UI 没变色。**P3 里程碑的深色模式验收项未真正达成。**

### 2.4 次要问题：App.tsx effect 冗余且有竞态

`App.tsx:15-24` 的 effect 在 `[theme]` 变化时，通过 `shadowRoot.querySelector('[data-bili-agent-root]')` 查找节点再设属性/class。但：

1. React 根 div 本身已在 `App.tsx:101` 通过 JSX 绑定了 `className={bili-agent-theme-${theme}}` 和 `data-theme={theme}`，effect 的 DOM 操作是**对同一节点的重复设置**，属于冗余代码。
2. effect 依赖 `[theme]`，首次执行时 useTheme 初始 state 为 `'light'`（默认值），后续 theme 变化触发时若 shadowRoot 内节点尚未挂载（Panel 条件渲染 + shadowRoot 注入时序），`root` 为 null 会静默跳过，存在竞态风险。

**注意**：此 effect 非根因，即使删除也不影响——因为 JSX 已绑定属性。真正缺失的是 CSS。

## 四、影响评估

### 4.1 功能影响

- **直接影响**：深色模式功能 100% 失效，用户切换后 UI 完全不变色
- **次级影响**：auto 模式同样失效（即使系统为深色，面板仍为浅色，因为 CSS 无 `@media (prefers-color-scheme: dark)` 规则）
- **用户体验**：在深色环境（夜间、系统深色主题）下，面板白色高亮刺眼

### 4.2 代码质量影响

- `App.tsx:15-24` 的 effect 为冗余代码，增加维护成本与竞态风险
- 70+ 处硬编码颜色违背"单一数据源"原则，未来调色需逐处修改

### 4.3 测试覆盖影响

- 缺失深色模式视觉/样式断言测试
- e2e 无深色模式用例（`实施方案 4.3-P3-UI完整.md:148` 验收项无对应 e2e）

## 五、修复方案

### 5.1 推荐方案：CSS 变量化重构（治本）

**思路**：将 styles.ts 顶部的 `:host` 块改造为变量定义区，按 light/dark 作用域分别赋值，所有硬编码颜色改为 `var(--xxx)` 引用。

**改造结构**：

```css
/* styles.ts 顶部 */
:host {
  all: initial;
  font-family: ...;
}

/* 浅色变量集（默认） */
[data-bili-agent-root],
.bili-agent-theme-light {
  --bg: #FFFFFF;
  --bg-soft: #F4F5F7;
  --bg-card-head: #FFF5F7;
  --text: #18191C;
  --text-muted: #61666D;
  --text-subtle: #9499A0;
  --border: #E5E9EF;
  --primary: #FB7299;
  --primary-dark: #F25D8E;
  --warning-bg: #FFF7E6;
  --error-bg: #FFF1F0;
  /* ... 其余变量按 TOKENS 清单补全 */
}

/* 深色变量集（覆盖） */
.bili-agent-theme-dark {
  --bg: #1F1F1F;
  --bg-soft: #2A2A2A;
  --bg-card-head: #2D2228;
  --text: #E8E8E8;
  --text-muted: #A0A0A0;
  --text-subtle: #707070;
  --border: #3A3A3A;
  --primary: #FB7299;       /* B站粉保持品牌色 */
  --primary-dark: #F25D8E;
  --warning-bg: #3D3520;
  --error-bg: #3D2020;
}

/* auto 模式 fallback：系统深色时自动应用深色变量 */
@media (prefers-color-scheme: dark) {
  .bili-agent-theme-auto {
    /* 同 .bili-agent-theme-dark 的变量覆盖 */
  }
}
```

**后续**：将 70+ 处 `background-color: #FFFFFF` 改为 `background-color: var(--bg)`，逐项替换。

### 5.2 备选方案：深色覆盖层（治标，快速止血）

不改原有规则，在 styles.ts 尾部新增大块深色覆盖：

```css
.bili-agent-theme-dark .bili-agent-panel { background-color: #1F1F1F; }
.bili-agent-theme-dark .bili-agent-message-user { ... }
/* ... 需为每个需要变色的选择器写覆盖块 */
```

**缺点**：需重复 70+ 选择器，维护性差，容易遗漏新增组件。

### 5.3 临时规避方案：隐藏 dark 选项

在 `SettingsPanel.tsx:415` 的主题 radio 中临时禁用 dark 选项，待 CSS 改造完成后放出。**非修复，仅规避用户感知。**

### 5.4 冗余 effect 清理（附带修复）

无论选哪个方案，都应同步清理 `App.tsx:15-24` 的冗余 effect：

- 删除整个 `useEffect(() => { ... }, [theme])` 块
- 保留 `App.tsx:101` 的 JSX 属性绑定即可（React 会自动同步）
- 如需保留 effect 作防御性代码，应改为对 `document.documentElement` 或确保节点存在后再操作，并去除与 JSX 的重复
