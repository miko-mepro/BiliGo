## 发现的问题清单

### 问题 1 · ⑦并发/资源泄漏 · 🟡警告

- **位置**：`src/config/session-memory.ts:53-82`
- **问题**：`updateSessionMemory` 采用 read-then-write 模式，存在 TOCTOU 竞态。两个并发调用同时读取同一 conversationId，各自 merge patch 后写回，后写者覆盖先写者。
- **修复建议**：对同一 conversationId 的写入加串行化队列（Promise 链）。

### 问题 2 · ⑦并发/资源泄漏 · 🔵建议

- **位置**：`src/config/session-memory.ts:76`
- **问题**：每次调用 `updateSessionMemory` 都 `new TextEncoder()`。
- **修复建议**：提升为模块级单例 `const textEncoder = new TextEncoder()`。

### 问题 3 · ⑧性能问题 · 🟡警告

- **位置**：`src/config/origin-pattern.ts:109-123,154`
- **问题**：`collectBuiltInHostnames()` 每次调用 `isBuiltInProviderOrigin` 都遍历 BUILT_IN_PROVIDERS 并创建新数组。BUILT_IN_PROVIDERS 是静态常量，应缓存。
- **修复建议**：用 IIFE 缓存为模块级常量 `BUILT_IN_HOSTNAMES`。

### 问题 4 · ⑩错误处理缺失 · 🟠严重

- **位置**：`src/config/session-memory.ts:82`
- **问题**：`chrome.storage.session.set` 如果抛异常，异常直接传播。但函数签名返回 `Promise<boolean>`，调用方期望所有失败情况返回 `false`。
- **修复建议**：包裹 try-catch，配额/IO 失败时返回 false。

### 问题 5 · ⑩错误处理缺失 · 🟡警告

- **位置**：`src/config/provider-factory.ts:7-25`
- **问题**：`createModel` 的 switch 没有 default 分支。运行时如果脏数据绕过类型检查，函数隐式返回 `undefined`。
- **修复建议**：添加 default 分支抛出明确错误。

### 问题 6 · ⑩错误处理缺失 · 🟡警告

- **位置**：`src/config/settings.ts:29-40`
- **问题**：`readBiliAgentSettings` 和 `saveBiliAgentSettings` 直接 await `chrome.storage.local`，无 try-catch。storage 操作失败时异常传播到 UI 层可能导致设置面板崩溃。
- **修复建议**：添加 try-catch，存储失败时回退默认设置或抛出可识别错误。

### 问题 7 · ⑫测试覆盖盲区 · 🟡警告

- **位置**：`test/config/`（缺失）
- **问题**：`settings.ts` 无测试文件。`readBiliAgentSettings`/`saveBiliAgentSettings`/`normalizeSettings` 三个导出函数均无直接测试。
- **修复建议**：新建 `test/config/settings.test.ts`。

### 问题 8 · ⑫测试覆盖盲区 · 🟡警告

- **位置**：`test/config/provider-factory.test.ts`（缺失场景）
- **问题**：`createModel` 无非法 format 值测试。`validateProviderConfig` 无 baseUrl 为空、model 为空、format 非法值的测试。
- **修复建议**：补充防御性测试。

### 问题 9 · ⑫测试覆盖盲区 · 🟡警告

- **位置**：`test/config/session-memory.test.ts`（缺失场景）
- **问题**：无 `chrome.storage.session.get/set/remove` 抛异常的场景测试。无并发写入竞态测试。
- **修复建议**：补充异常路径测试。

## 审计结论

**最高优先级修复**：问题 4（🟠，session-memory set 异常不返回 false）和问题 5（createModel switch 无 default）。
