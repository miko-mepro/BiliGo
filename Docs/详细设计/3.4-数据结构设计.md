## 1. ChatState 状态结构

### 1.1 完整定义

```typescript
interface ChatState {
  // 对话数据
  messages: ChatMessage[];              // 对话消息列表
  videos: BilibiliVideoCard[];          // 当前搜索结果视频
  conversationId: string;               // 会话 ID

  // 流式状态
  streamingContent: string;             // 流式文本累积（未提交到 messages）
  streamingReasoning: string;           // 推理过程文本累积

  // UI 状态
  isLoading: boolean;                    // 加载状态
  error: ErrorPayload | null;            // 错误信息
  activity: AgentActivity | null;        // 当前活动状态
  hydrated: boolean;                     // 是否已从存储恢复

  // 工具洞察（时间线展示）
  understandings: TimedUnderstanding[];  // 黑话理解结果
  expansions: TimedExpansion[];          // 查询扩展结果
  reranks: TimedRerank[];                // 重排结果
  clarification: ClarificationRequest | null;  // 澄清请求
}

interface TimedUnderstanding extends SlangUnderstandResult {
  receivedAt: number;
}
interface TimedExpansion extends QueryExpandResult {
  receivedAt: number;
}
interface TimedRerank extends RerankResult {
  receivedAt: number;
}

interface AgentActivity {
  kind: 'thinking' | 'responding' | 'tool';
  label?: string;    // 工具名等
}
```

### 1.2 初始状态

```typescript
const initialState: ChatState = {
  messages: [],
  videos: [],
  conversationId: generateConversationId(),  // 'conv_' + Date.now() + random
  streamingContent: '',
  streamingReasoning: '',
  isLoading: false,
  error: null,
  activity: null,
  hydrated: false,
  understandings: [],
  expansions: [],
  reranks: [],
  clarification: null,
};
```

### 1.3 字段职责

| 字段 | 写入时机 | 读取方 | 持久化 |
|------|---------|--------|--------|
| messages | ADD_MESSAGE / HYDRATE | MessageList | ✅ ConversationData |
| videos | SET_VIDEOS / HYDRATE | VideoCard[] | ✅ ConversationData |
| conversationId | 初始化 / HYDRATE | 持久化 key | ✅ |
| streamingContent | APPEND_STREAMING / CLEAR_STREAMING | ChatMessage 流式渲染 | ❌（临时） |
| streamingReasoning | APPEND_REASONING / CLEAR_STREAMING | ChatMessage reasoning 折叠 | ❌（临时） |
| isLoading | SET_LOADING | 输入框禁用、activity 指示 | ❌ |
| error | SET_ERROR | ErrorDisplay | ❌ |
| activity | SET_ACTIVITY | activity 指示器 | ❌ |
| hydrated | HYDRATE | 是否跳过自动恢复 | ❌ |
| understandings | ADD_UNDERSTANDING / HYDRATE | AgentInsightCard | ✅ ConversationData |
| expansions | ADD_EXPANSION / HYDRATE | AgentInsightCard | ✅ ConversationData |
| reranks | ADD_RERANK / HYDRATE | AgentInsightCard | ✅ ConversationData |
| clarification | SET_CLARIFICATION / CLEAR / HYDRATE | AgentInsightCard | ❌（会话级） |

## 2. ChatAction 状态机

### 2.1 Action 完整定义

```typescript
type ChatAction =
  | { type: 'ADD_MESSAGE'; payload: ChatMessage }
  | { type: 'SET_LOADING'; payload: boolean }
  | { type: 'SET_ERROR'; payload: ErrorPayload | null }
  | { type: 'SET_VIDEOS'; payload: BilibiliVideoCard[] }
  | { type: 'APPEND_STREAMING'; payload: string }
  | { type: 'APPEND_REASONING'; payload: string }
  | { type: 'SET_ACTIVITY'; payload: AgentActivity | null }
  | { type: 'ADD_STEP'; payload: AgentStep }
  | { type: 'CLEAR_STREAMING' }
  | { type: 'UPDATE_LAST_MESSAGE'; payload: { content: string; reasoning?: string } }
  | { type: 'CLEAR_MESSAGES' }
  | { type: 'HYDRATE'; payload: PersistedConversation | null }
  | { type: 'REHYDRATE'; payload: PersistedConversation }
  | { type: 'ADD_UNDERSTANDING'; payload: SlangUnderstandResult }
  | { type: 'ADD_EXPANSION'; payload: QueryExpandResult }
  | { type: 'ADD_RERANK'; payload: RerankResult }
  | { type: 'SET_CLARIFICATION'; payload: ClarificationRequest }
  | { type: 'CLEAR_CLARIFICATION' };
```

### 2.2 Reducer 转换规则

```typescript
function chatReducer(state: ChatState, action: ChatAction): ChatState {
  switch (action.type) {
    case 'ADD_MESSAGE':
      return { ...state, messages: [...state.messages, action.payload] };

    case 'SET_LOADING':
      return { ...state, isLoading: action.payload };

    case 'SET_ERROR':
      return { ...state, error: action.payload };

    case 'SET_VIDEOS':
      return { ...state, videos: action.payload };

    case 'APPEND_STREAMING':
      return { ...state, streamingContent: state.streamingContent + action.payload };

    case 'APPEND_REASONING':
      return { ...state, streamingReasoning: state.streamingReasoning + action.payload };

    case 'SET_ACTIVITY':
      return { ...state, activity: action.payload };

    case 'ADD_STEP': {
      const messages = [...state.messages];
      const last = messages[messages.length - 1];
      if (last && last.role === 'assistant') {
        messages[messages.length - 1] = {
          ...last,
          steps: [...(last.steps ?? []), action.payload],
        };
      }
      return { ...state, messages };
    }

    case 'CLEAR_STREAMING':
      return { ...state, streamingContent: '', streamingReasoning: '' };

    case 'UPDATE_LAST_MESSAGE': {
      const messages = [...state.messages];
      const last = messages[messages.length - 1];
      if (last && last.role === 'assistant') {
        messages[messages.length - 1] = {
          ...last,
          content: action.payload.content,
          reasoning: action.payload.reasoning ?? last.reasoning,
        };
      }
      return { ...state, messages };
    }

    case 'CLEAR_MESSAGES':
      return {
        ...initialState,
        conversationId: generateConversationId(),
        hydrated: true,
      };

    case 'HYDRATE':
      if (!action.payload) {
        return { ...state, hydrated: true };
      }
      return {
        ...state,
        messages: action.payload.messages,
        videos: action.payload.videos,
        conversationId: action.payload.conversationId,
        understandings: action.payload.understandings,
        expansions: action.payload.expansions,
        reranks: action.payload.reranks,
        hydrated: true,
      };

    case 'REHYDRATE':
      return {
        ...state,
        messages: action.payload.messages,
        videos: action.payload.videos,
        conversationId: action.payload.conversationId,
        understandings: action.payload.understandings,
        expansions: action.payload.expansions,
        reranks: action.payload.reranks,
        hydrated: true,
      };

    case 'ADD_UNDERSTANDING':
      return {
        ...state,
        understandings: [
          ...state.understandings,
          { ...action.payload, receivedAt: Date.now() },
        ],
      };

    case 'ADD_EXPANSION':
      return {
        ...state,
        expansions: [
          ...state.expansions,
          { ...action.payload, receivedAt: Date.now() },
        ],
      };

    case 'ADD_RERANK':
      return {
        ...state,
        reranks: [
          ...state.reranks,
          { ...action.payload, receivedAt: Date.now() },
        ],
      };

    case 'SET_CLARIFICATION':
      return { ...state, clarification: action.payload };

    case 'CLEAR_CLARIFICATION':
      return { ...state, clarification: null };

    default:
      return state;
  }
}
```

## 4. Port 消息 -> Action 映射（AI SDK 适配）

### 4.1 映射表

| Port 消息 (SWMessage) | dispatch Action | 副作用 |
|----------------------|----------------|--------|
| `{type:'chunk', delta}` | `APPEND_STREAMING` | 首次 chunk 时 `SET_ACTIVITY(responding)` |
| `{type:'reasoning', delta}` | `APPEND_REASONING` | - |
| `{type:'tool_start', toolName, args}` | `SET_ACTIVITY(tool)` + `ADD_STEP` | - |
| `{type:'tool_result', toolName, result}` | （存入当前 step） | - |
| `{type:'videos', videos}` | `SET_VIDEOS` | - |
| `{type:'insight', kind, data}` | 见 §4.2 | - |
| `{type:'done'}` | `CLEAR_STREAMING` + `UPDATE_LAST_MESSAGE` + `SET_LOADING(false)` + `SET_ACTIVITY(null)` | 触发历史保存 |
| `{type:'error', message, code}` | `SET_ERROR` + `SET_LOADING(false)` + `SET_ACTIVITY(null)` | - |
| `{type:'pong'}` | （重置超时） | - |

### 4.2 insight -> Action 映射

```typescript
switch (msg.kind) {
  case 'understanding':
    dispatch({ type: 'ADD_UNDERSTANDING', payload: msg.data });
    break;
  case 'expansion':
    dispatch({ type: 'ADD_EXPANSION', payload: msg.data });
    break;
  case 'rerank':
    dispatch({ type: 'ADD_RERANK', payload: msg.data });
    break;
  case 'clarification':
    dispatch({ type: 'SET_CLARIFICATION', payload: msg.data });
    break;
}
```

### 4.3 done 的复合处理

收到 `done` 后，CS 端需执行**多个 dispatch**（顺序重要）：

```typescript
case 'done': {
  // 1. 把累积的流式内容提交为 assistant message
  if (state.streamingContent) {
    dispatch({
      type: 'ADD_MESSAGE',
      payload: {
        role: 'assistant',
        content: state.streamingContent,
        reasoning: state.streamingReasoning || undefined,
        timestamp: Date.now(),
      },
    });
  }
  // 2. 清空流式状态
  dispatch({ type: 'CLEAR_STREAMING' });
  // 3. 结束 loading
  dispatch({ type: 'SET_LOADING', payload: false });
  // 4. 清除 activity
  dispatch({ type: 'SET_ACTIVITY', payload: null });
  // 5. 触发历史保存
  triggerHistorySave();
  break;
}
```

## 6. 保存编排（save-orchestrator）

### 6.1 4 个保存触发点

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 本地缓存防抖 (300ms)                                     │
│    state 变更 -> debounce(300ms) -> 写 'bili-agent-conversation'│
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│ 2. HISTORY_SAVE_EVENT 监听                                   │
│    面板关闭时触发 -> 立即保存到历史                           │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│ 3. beforeunload 监听                                         │
│    页面卸载时触发 -> 立即保存                                 │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│ 4. 首次启用历史的迁移                                        │
│    索引为空 + 存在存储对话 -> 迁移到历史索引                  │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 保存流程

```typescript
function useConversationSaver(state: ChatState) {
  // 1. 本地缓存防抖
  useEffect(() => {
    const timer = setTimeout(() => {
      saveLocalCache(state);  // -> 'bili-agent-conversation'
    }, 300);
    return () => clearTimeout(timer);
  }, [state]);

  // 2. 历史保存事件
  useEffect(() => {
    const handler = () => saveToHistory(state);
    window.addEventListener(HISTORY_SAVE_EVENT, handler);
    return () => window.removeEventListener(HISTORY_SAVE_EVENT, handler);
  }, [state]);

  // 3. 卸载保存
  useEffect(() => {
    const handler = () => saveToHistory(state);
    window.addEventListener('beforeunload', handler);
    return () => window.removeEventListener('beforeunload', handler);
  }, [state]);
}

async function saveToHistory(state: ChatState) {
  const data: ConversationData = {
    version: 2,
    id: state.conversationId,
    messages: state.messages.slice(-MAX_PERSISTED_MESSAGES),  // 最多 200
    videos: state.videos,
    understandings: state.understandings,
    expansions: state.expansions,
    reranks: state.reranks,
    createdAt: Date.now(),
    lastActiveAt: Date.now(),
  };
  await saveConversation(data);  // -> 'bili-agent-history:{id}'

  // 更新索引
  const index = await getHistoryIndex();
  const existing = index.find(r => r.id === data.id);
  const record: ConversationRecord = {
    id: data.id,
    title: existing?.title || generateTitle(data.messages),
    titleFinal: existing?.titleFinal || false,
    createdAt: existing?.createdAt || data.createdAt,
    lastActiveAt: data.lastActiveAt,
    messageCount: data.messages.length,
  };
  await writeHistoryIndex(updateOrInsert(index, record).slice(0, MAX_HISTORY));
}
```

## 7. 跨标签页同步（HistorySync）

### 7.1 同步机制

```typescript
class HistorySync {
  private syncId: string;
  private pendingWriteId: string | null;
  private readonly TTL = 200;  // ms

  start(callback: () => void) {
    chrome.storage.onChanged.addListener((changes, area) => {
      if (area !== 'local') return;
      const indexChange = changes['bili-agent-history-index'];
      if (!indexChange) return;

      const newIndex = indexChange.newValue;
      const writeId = newIndex?.__syncId;
      if (writeId === this.syncId) return;  // 自身写入，忽略
      if (writeId === this.pendingWriteId) return;  // pending 期内，忽略

      callback();  // 重新加载历史索引
    });
  }

  trackedWrite(index: ConversationRecord[]) {
    this.syncId = generateSyncId();
    this.pendingWriteId = this.syncId;
    setTimeout(() => { this.pendingWriteId = null; }, this.TTL);
    // 写入时附加 __syncId
    chrome.storage.local.set({
      'bili-agent-history-index': { ...index, __syncId: this.syncId },
    });
  }
}
```

### 7.2 syncId 机制说明

- 每次写入生成唯一 `syncId`
- 写入后的 200ms 内（pending），其他标签页收到通知会忽略相同 `syncId`
- 避免自身写入触发回调导致重复刷新

## 9. AI SDK 迁移适配

### 9.1 简化的状态字段

迁移后，以下字段可简化或移除：

| 字段 | 旧版 | 新版（AI SDK） | 变化 |
|------|------|---------------|------|
| `streamingContent` | 手动累积 delta | 不变（仍需累积 UI 渲染） | 保留 |
| `streamingReasoning` | 手动累积 | 不变 | 保留 |
| `activity` | 手动判断 thinking/responding | 由 fullStream 事件推断 | 简化 |
| `steps`（在 message 内） | 手动 ADD_STEP | 由 tool_start 事件驱动 | 不变 |

### 9.2 移除的字段

旧版 ChatContext 手动维护 tool loop，需跟踪 `assistantToolCalls`、`requestedTool` 等中间状态。迁移后由 AI SDK 内部处理，**这些中间变量移除**：

```typescript
// 旧版（移除）
let requestedTool = false;
let assistantContent = '';
let announcedResponding = false;
const assistantToolCalls: ToolCall[] = [];

// 新版（AI SDK 自动）
const result = streamText({ model, system, messages, tools, stopWhen: stepCountIs(5) });
for await (const part of result.fullStream) { /* 直接 dispatch */ }
```

### 9.3 双 Port -> 单 Port 的状态影响

旧版 CS 端维护两个 Port（`bili-agent-llm` + `bili-agent-chat`），各有连接状态。新版合并为单 Port，状态简化：

```typescript
// 旧版
const llmPort = chrome.runtime.connect({ name: 'bili-agent-llm' });
const chatPort = chrome.runtime.connect({ name: 'bili-agent-chat' });
// 两个 Port 的生命周期分别管理

// 新版
const port = chrome.runtime.connect({ name: 'bili-agent-chat' });
// 单 Port，生命周期简单
```

## 10. 状态不变量（Invariants）

实现时必须保证以下不变量，违反即视为 bug：

| # | 不变量 | 验证方法 |
|---|--------|---------|
| I1 | `isLoading=true` 时必有 `activity!=null` 或正在等待首个 chunk | 检查 reducer 转换 |
| I2 | `streamingContent` 非空时 `isLoading` 必为 true | 检查 CLEAR_STREAMING 时机 |
| I3 | 收到 `done` 后 `streamingContent` 必为空 | CLEAR_STREAMING 在 done 处理内 |
| I4 | `error!=null` 时 `isLoading` 必为 false | SET_ERROR 同时 SET_LOADING false |
| I5 | `conversationId` 在会话期间不变，CLEAR_MESSAGES 时重生成 | 检查 HYDRATE 不覆盖现有 id |
| I6 | `understandings`/`expansions`/`reranks` 单调递增（只追加） | 检查无删除逻辑 |
| I7 | `clarification` 每会话最多 1 个（SET 后不再 SET） | 由工具频率限制保证 |
| I8 | `messages` 最后一条为 assistant 时，ADD_STEP 才生效 | 检查 last.role |
| I9 | 持久化的 messages 不超过 MAX_PERSISTED_MESSAGES(200) | slice 截断 |
| I10 | 历史索引不超过 MAX_HISTORY(50) | slice 截断 |
