# 3.2 协议设计

> 子流程：通信消息格式、错误码、时序
> 来源：旧仓库 `router.ts` 双 Port 机制 + `ChatContext.tsx` tool loop；迁移后合并为单 Port
> 判定标准：两个开发者拿着此文档独立实现 CS/SW 端，消息能正确互通

---

## 1. 架构变化：双 Port -> 单 Port

### 旧版（已废弃）

旧仓库（`router.ts:96-128` + `ChatContext.tsx:877-1027`）使用**两个 Port**：
- `bili-agent-llm`：CS -> SW 发送 `llm_chat` 请求，接收 `llm_envelope` 流式回复
- `bili-agent-chat`：CS -> SW 发送 `tool_call` 请求，接收 `tool_result` 结果

旧版 CS 端手动维护 tool loop（`streamViaLlmAdapter`，~75 行），每轮判断是否需要工具，再通过 `bili-agent-chat` Port 发工具调用。

### 新版（AI SDK 架构）

**单 Port**：`bili-agent-chat`

```
CS ──postMessage(chat)──> SW
   <──postMessage(chunk)────  (流式文本)
   <──postMessage(reasoning)─ (推理流)
   <──postMessage(tool_start)─ (工具开始，自动)
   <──postMessage(tool_result) (工具结果，自动)
   <──postMessage(videos)────  (视频列表)
   <──postMessage(insight)──── (洞察卡片)
   <──postMessage(done)──────  (完成)
   <──postMessage(error)─────  (错误)
```

工具执行完全在 SW 内部由 AI SDK `streamText` 自动驱动，CS 端不再参与 tool loop。

## 2. Port 连接建立

### 2.1 CS 端发起连接

```typescript
// content/port-connection.ts
const port = chrome.runtime.connect({ name: 'bili-agent-chat' });
```

**Port 名称**：`'bili-agent-chat'`（必须与 SW 监听一致）

### 2.2 SW 端监听

```typescript
// background/index.ts
chrome.runtime.onConnect.addListener((port) => {
  if (port.name !== 'bili-agent-chat') return;

  const state = { disconnected: false };
  port.onDisconnect.addListener(() => {
    state.disconnected = true;
  });

  port.onMessage.addListener((msg: CSMessage) => {
    // 见 §3 消息定义
  });
});
```

### 2.3 断连检测

- CS 端：`port.onDisconnect` -> 触发 `SET_ERROR { message:'连接已断开，请重试' }`
- SW 端：`state.disconnected = true`，后续 `postToPort` 静默丢弃消息（避免对已断开 Port 报错）

## 3. CS -> SW 消息（CSMessage）

```typescript
type CSMessage =
  | { type: 'chat'; messages: ChatMessage[]; conversationId: string }
  | { type: 'generate_title'; conversationId: string; messages: ChatMessage[] }
  | { type: 'stop' }
  | { type: 'ping' }
  | { type: 'test_connection'; provider: ProviderConfig };   // 连接测试请求（P5 新增）
```

### 3.1 `chat` - 发起对话

```json
{
  "type": "chat",
  "messages": [
    { "role": "user", "content": "yyds的鬼畜视频", "timestamp": 1720704000000 }
  ],
  "conversationId": "conv_abc123"
}
```

**字段约束**：
- `messages`：包含已提交的完整对话历史和本轮 user（CS 端每次发送全量），不包含仅用于流式 UI 的空 assistant 占位消息
- `conversationId`：CS 端生成（`generateConversationId()`），用于持久化和工具 traceId

**SW 收到后**：
1. 读取 settings 获取 activeProvider
2. `createModel(provider)` 创建 AI SDK model
3. `toModelMessages(messages)` 去除 UI 专用字段；系统提示只通过 `system` 参数传入，避免重复注入
4. 调用 `streamText({ model, system, messages: modelMessages, tools, stopWhen: isStepCount(5) })`
5. 遍历 `result.stream` 推流（`fullStream` 在 ai@7.0.22 中仅为 deprecated alias）

### 3.2 `generate_title` - 请求生成对话标题（P4 新增）

```json
{
  "type": "generate_title",
  "conversationId": "conv_abc123",
  "messages": [
    { "role": "user", "content": "yyds的鬼畜视频", "timestamp": 1720704000000 },
    { "role": "assistant", "content": "为你找到这些…", "timestamp": 1720704005000 }
  ]
}
```

**触发时机**：对话首次保存且 `titleFinal=false` 时，CS 取前 2 条消息经单 Port 发起（复用 `bili-agent-chat`，向后兼容：旧 SW 收到未知类型直接忽略，CS 走本地降级）。

**SW 收到后**：
1. 读取 settings 获取 activeProvider（与 `chat` 相同的配置链路）
2. `createModel(provider)` 创建 AI SDK model
3. 调用 `generateText({ model, messages, system: 标题生成提示 })`，无工具循环，10s 超时
4. 标题截断为 20 字内，回复 `{ type: 'title'; conversationId; title }`
5. 失败（无配置/网络/超时）时回复 `{ type: 'error'; message; code? }`，CS 端降级用首条 user 消息前 20 字并置 `titleFinal=true`

### 3.3 `stop` - 中断生成

```json
{ "type": "stop" }
```

**SW 收到后**：调用 `AbortController.abort()`。实现需同时兼容 `result.stream` 产出 `abort` part 和迭代过程中抛出 `AbortError`，两种情况均静默结束并发送 `{type:'done'}`。

### 3.4 `ping` - 心跳保活

```json
{ "type": "ping" }
```

**发送频率**：每 25 秒一次（应对 MV3 SW 30s 休眠，见风险 R1）
**SW 收到后**：立即回复 `{type:'pong'}`

### 3.5 `test_connection` - 连接测试请求（P5 新增）

```json
{
  "type": "test_connection",
  "provider": {
    "id": "deepseek",
    "name": "DeepSeek",
    "format": "openai",
    "baseUrl": "https://api.deepseek.com/v1",
    "apiKey": "sk-xxx",
    "model": "deepseek-chat",
    "isBuiltIn": true,
    "isCustom": false
  }
}
```

**触发时机**：用户在设置面板点击"测试连接"按钮时，CS 经单 Port 发送待测 provider 配置。

**SW 收到后**：
1. 先调 `validateProviderConfig(provider)` 校验（ollama 允许空 apiKey）
2. 校验通过后用 `msg.provider` 调 `createModel(provider)` 创建临时 model（不读取 settings，直接用消息携带的配置）
3. 执行 `generateText({ model, messages: [{ role: 'user', content: 'hi' }], abortSignal: AbortSignal.timeout(10_000) })`，10s 超时
4. 成功回复 `{ type: 'connection_result', ok: true }`
5. 失败回复 `{ type: 'connection_result', ok: false, error: friendlyMessage(code, message) }`

**注意**：此消息不经 streamText，不触发工具循环，仅做一次性连通性验证。

## 4. SW -> CS 消息（SWMessage）

```typescript
type SWMessage =
  | { type: 'chunk'; delta: string }                                    // 文本流
  | { type: 'reasoning'; delta: string }                                // 推理流
  | { type: 'tool_start'; toolCallId: string; toolName: string; args: unknown }   // 工具开始
  | { type: 'tool_result'; toolCallId: string; toolName: string; result: unknown } // 工具结果
  | { type: 'videos'; videos: BilibiliVideoCard[] }                    // 视频列表
  | { type: 'insight'; kind: InsightKind; data: unknown }             // 洞察数据
  | { type: 'done' }                                                    // 完成
  | { type: 'error'; message: string; code?: string }                  // 错误
  | { type: 'title'; conversationId: string; title: string }         // 标题生成结果（P4 新增）
  | { type: 'connection_result'; ok: boolean; error?: string }   // 连接测试结果（P5 新增）
  | { type: 'pong' };                                                   // 心跳响应

type InsightKind = 'understanding' | 'expansion' | 'rerank' | 'clarification';
```

### 4.1 `chunk` - 文本流增量

```json
{ "type": "chunk", "delta": "根据" }
{ "type": "chunk", "delta": "你的" }
{ "type": "chunk", "delta": "搜索" }
```

**来源**：AI SDK `stream` 的 `text-delta` 事件
**CS 处理**：`dispatch({ type:'APPEND_STREAMING', payload: delta })`

### 4.2 `reasoning` - 推理流增量

```json
{ "type": "reasoning", "delta": "用户想找鬼畜视频..." }
```

**来源**：AI SDK `stream` 的 `reasoning-delta` 事件（DeepSeek 等），读取 `part.text`
**CS 处理**：`dispatch({ type:'APPEND_REASONING', payload: delta })`

### 4.3 `tool_start` - 工具开始

```json
{
  "type": "tool_start",
  "toolCallId": "call_search_1",
  "toolName": "bilibili_search",
  "args": { "keyword": "鬼畜", "order": "totalrank" }
}
```

**来源**：AI SDK `stream` 的 `tool-call` 事件
**CS 处理**：
```typescript
ensureAssistantPlaceholder();
dispatch({ type: 'SET_ACTIVITY', payload: { kind: 'tool', label: toolName } });
dispatch({
  type: 'ADD_STEP',
  payload: {
    id: toolCallId,
    type: 'tool_call',
    name: toolName,
    summary: '...',
    status: 'running',
    timestamp: Date.now(),
  },
});
```

### 4.4 `tool_result` - 工具结果

```json
{
  "type": "tool_result",
  "toolCallId": "call_search_1",
  "toolName": "bilibili_search",
  "result": [{ "bvid": "BV1xx411c7mD", "title": "..." }]
}
```

**来源**：AI SDK `stream` 的 `tool-result` 事件
**CS 处理**：按 `toolCallId` dispatch `COMPLETE_STEP`，只把对应步骤标为完成；原始 `result` 不写入 ChatState，视频和洞察分别由 `videos` / `insight` 消息承载。

### 4.5 `videos` - 视频列表

```json
{
  "type": "videos",
  "videos": [{ "bvid": "BV1xx411c7mD", "title": "【鬼畜】永远的神", "..." }]
}
```

**触发时机**：
1. `bilibili_search` 工具执行后立即推送搜索结果
2. `video_rerank` 工具执行后推送重排后的列表

**CS 处理**：`dispatch({ type:'SET_VIDEOS', payload: videos })`

### 4.6 `insight` - 洞察数据

```json
{
  "type": "insight",
  "kind": "understanding",
  "data": {
    "original": "yyds的鬼畜视频",
    "normalized": "永远的神 鬼畜视频",
    "explanation": "yyds=永远的神",
    "matchedDict": true
  }
}
```

**kind 枚举**：
| kind | 对应工具 | data 类型 | CS dispatch |
|------|---------|----------|-------------|
| `understanding` | slang_understand | `SlangUnderstandResult` | `ADD_UNDERSTANDING` |
| `expansion` | query_expand | `QueryExpandResult` | `ADD_EXPANSION` |
| `rerank` | video_rerank | `RerankResult` | `ADD_RERANK` |
| `clarification` | ask_clarification | `ClarificationRequest` | `SET_CLARIFICATION` |

### 4.7 `done` - 完成

```json
{ "type": "done" }
```

**触发时机**：`stream` 遍历结束，或被 `stop` 中断
**CS 处理**：
```typescript
// 如果整个请求在首个流事件前结束，此时不存在 assistant，占位更新为安全 no-op。
const current = stateRef.current;
dispatch({
  type: 'UPDATE_LAST_MESSAGE',
  payload: {
    content: current.streamingContent,
    reasoning: current.streamingReasoning || undefined,
  },
});
dispatch({ type:'CLEAR_STREAMING' });
dispatch({ type:'SET_LOADING', payload:false });
dispatch({ type:'SET_ACTIVITY', payload:null });
// 触发历史保存（save-orchestrator）
```

### 4.8 `error` - 错误

```json
{ "type": "error", "message": "API Key 无效，请检查设置", "code": "401" }
```

**CS 处理**：`dispatch({ type:'SET_ERROR', payload: { message, code } })`

### 4.9 `title` - 标题生成结果（P4 新增）

```json
{ "type": "title", "conversationId": "conv_abc123", "title": "鬼畜视频推荐" }
```

**触发时机**：SW 完成 `generate_title` 请求后推送。`title` 已截断为 20 字以内。
**CS 处理**：仅当 `conversationId` 与当前活动会话一致时采纳：`store.updateTitle(conversationId, title)`（置 `titleFinal=true`），并派发 `HISTORY_INDEX_DIRTY_EVENT` 刷新历史下拉；失败或超时则用首条 user 消息前 20 字做本地降级。

### 4.10 `pong` - 心跳响应

```json
{ "type": "pong" }
```

**CS 处理**：重置 60s 超时计时器

### 4.11 `connection_result` - 连接测试结果（P5 新增）

```json
{ "type": "connection_result", "ok": true }
```

或失败时：
```json
{ "type": "connection_result", "ok": false, "error": "API Key 无效，请检查设置" }
```

**触发时机**：SW 完成 `test_connection` 请求后推送。
**CS 处理**：TestConnectionButton 组件监听 `port.onMessage`，收到 `connection_result` 后更新按钮状态（ok=true -> 成功态，ok=false -> 失败态显示 error）。

## 5. stream -> Port 消息映射

SW 端消费 AI SDK `stream`，每个事件映射到 Port 消息：

```typescript
streamLoop: for await (const part of result.stream) {
  switch (part.type) {
    case 'text-delta':
      postToPort(port, state, { type: 'chunk', delta: part.text });
      break;

    case 'reasoning-delta':
      postToPort(port, state, { type: 'reasoning', delta: part.text });
      break;

    case 'tool-call':
      postToPort(port, state, {
        type: 'tool_start',
        toolCallId: part.toolCallId,
        toolName: part.toolName,
        args: part.input,    // AI SDK 7.x 字段名
      });
      break;

    case 'tool-result':
      postToPort(port, state, {
        type: 'tool_result',
        toolCallId: part.toolCallId,
        toolName: part.toolName,
        result: part.output,
      });
      // 见 §6 工具特定的额外消息推送
      break;

    case 'tool-error':
      postToPort(port, state, {
        type: 'error',
        message: friendlyMessage(part.error),
        code: inferCode(part.error),
      });
      break streamLoop;

    case 'abort':
      // 用户主动中断，静默结束；跳出事件循环后统一发送 done
      break streamLoop;

    case 'error':
      postToPort(port, state, {
        type: 'error',
        message: friendlyMessage(part.error),
        code: inferCode(part.error),
      });
      break streamLoop;
  }
}
postToPort(port, state, { type: 'done' });
```

**注意**：以上字段以本地 `ai@7.0.22` 类型为准：文本和推理增量均读取 `part.text`，工具事件读取 `part.toolCallId` / `part.input` / `part.output`。

## 6. 工具结果 -> 额外 Port 消息

每个工具的 `execute()` 返回值会被 AI SDK 自动作为 `tool-result` 推送。但为了 UI 即时渲染，SW 端在工具 `execute()` 内部或外部额外推送 `videos` / `insight` 消息：

### 6.1 bilibili_search

```typescript
execute: async ({ keyword, order, analyze_covers }) => {
  const sessdata = await getSessdata();
  const videos = await searchVideo(keyword, { order }, sessdata);

  if (analyze_covers) {
    await attachCoverDescriptions(videos);
  }

  // 额外推送视频列表给 CS
  postToPort(port, state, { type: 'videos', videos });

  return videos;  // 作为 tool-result
}
```

### 6.2 slang_understand / query_expand / video_rerank / ask_clarification

```typescript
execute: async (args) => {
  const result = await /* 工具逻辑 */;

  // 额外推送 insight
  postToPort(port, state, {
    type: 'insight',
    kind: 'understanding',  // 或 expansion/rerank/clarification
    data: result,
  });

  return result;
}
```

### 6.3 video_rerank 的双重推送

```typescript
execute: async ({ videos, intent }) => {
  const rerankResult = await rerank({ intent, candidates: videos, traceId });

  // 推送 insight
  postToPort(port, state, {
    type: 'insight', kind: 'rerank', data: rerankResult,
  });

  // 推送重排后的视频列表
  const reordered = rerankResult.items
    .map(item => videos.find(v => v.bvid === item.bvid))
    .filter(Boolean);
  postToPort(port, state, { type: 'videos', videos: reordered });

  return rerankResult;
}
```

## 7. 错误码表

| code | 含义 | 触发条件 | 用户提示 |
|------|------|---------|---------|
| `PROVIDER_NOT_CONFIGURED` | Provider 未配置 | 无 active provider，或 `validateProviderConfig()` 失败；Ollama 允许空 apiKey | 请到设置配置 AI 提供商 |
| `401` | 鉴权失败 | HTTP 401/403，含 "api key"/"auth" | API Key 无效，请检查设置 |
| `403` | 鉴权失败（同 401） | - | API Key 无效，请检查设置 |
| `429` | 限流 | HTTP 429，含 "rate limit" | 请求太频繁，请稍后重试 |
| `NETWORK_ERROR` | 网络异常 | fetch 失败、超时 | 网络连接失败 |
| `TOOL_ROUND_LIMIT` | 工具轮次超限（旧版兼容） | AI SDK `isStepCount(5)` 不触发；仅旧版兼容或应用层显式抛出时使用 | 工具调用次数过多，请换个说法再试 |
| `BILIBILI_RISK` | B站风控 | B站 API code=-352 | 触发风控，请稍后再试或登录 B站 |
| `BILIBILI_API` | B站 API 错误 | B站 API code 非 0 | B站接口异常 |
| `ABORTED` | 用户中断 | `AbortController.abort()` | （静默，不显示错误） |
| `VISION_UNSUPPORTED` | 视觉不支持 | Vision 模型返回 400/404 | 该模型不支持视觉，已降级 |

**推断规则**（来自旧 `ChatContext.tsx:1072-1081` `inferErrorCode`）：
```typescript
function inferErrorCode(message: string): string {
  const lower = message.toLowerCase();
  if (message.includes('401') || message.includes('403')
      || lower.includes('api key') || lower.includes('auth')) return '401';
  if (message.includes('429') || lower.includes('rate limit')) return '429';
  return 'NETWORK_ERROR';
}
```

## 9. 消息顺序保证

### 9.1 单 Port 内顺序

Chrome Port 的 `postMessage` 保证**同一 Port 内消息按发送顺序到达**。SW 端串行 `postToPort`，无需额外队列。

### 9.2 工具消息顺序约定

每个工具执行的消息顺序必须为：
1. `tool_start`（在 `execute` 前由 stream 的 `tool-call` 事件触发）
2. `videos` / `insight`（在 `execute` 内部推送）
3. `tool_result`（在 `execute` 返回后由 stream 的 `tool-result` 事件触发）

**违反此顺序会导致 UI 渲染异常**（如先收到 tool_result 再收到 videos，时间线会错位）。

### 9.3 done 的最终性

`done` 消息必须是会话的最后一条消息。CS 端收到 `done` 后：
- 把流式内容更新到生成开始时创建的 assistant 占位消息
- 清空 `streamingContent`
- 设置 `isLoading = false`
- 触发历史保存

**禁止在 `done` 之后再发送 `chunk` / `tool_*` 消息**。

## 10. 消息格式验证

### 10.1 CS 端消息验证（防御 SW 异常）

```typescript
function isSWMessage(value: unknown): value is SWMessage {
  if (!value || typeof value !== 'object') return false;
  const record = value as Record<string, unknown>;
  if (typeof record.type !== 'string') return false;

  switch (record.type) {
    case 'chunk':
    case 'reasoning':
      return typeof record.delta === 'string';
    case 'tool_start':
      return typeof record.toolCallId === 'string'
        && typeof record.toolName === 'string'
        && Object.hasOwn(record, 'args');
    case 'tool_result':
      return typeof record.toolCallId === 'string'
        && typeof record.toolName === 'string'
        && Object.hasOwn(record, 'result');
    case 'videos':
      return Array.isArray(record.videos);
    case 'insight':
      return ['understanding', 'expansion', 'rerank', 'clarification'].includes(
        String(record.kind),
      ) && Object.hasOwn(record, 'data');
    case 'done':
    case 'pong':
      return true;
    case 'connection_result':
      return typeof record.ok === 'boolean'
        && (record.error === undefined || typeof record.error === 'string');
    case 'error':
      return typeof record.message === 'string'
        && (record.code === undefined || typeof record.code === 'string');
    default:
      return false;
  }
}
```

### 10.2 SW 端消息验证

```typescript
function isCSMessage(value: unknown): value is CSMessage {
  if (!value || typeof value !== 'object') return false;
  const record = value as Record<string, unknown>;
  switch (record.type) {
    case 'chat':
      return Array.isArray(record.messages)
        && typeof record.conversationId === 'string'
        && record.conversationId.length > 0;
    case 'stop':
    case 'ping':
      return true;
    case 'test_connection':
      return record.provider !== null
        && typeof record.provider === 'object'
        && !Array.isArray(record.provider);
    default:
      return false;
  }
}
```

## 11. 兼容性与迁移注意

### 11.1 旧版双 Port 消息（已废弃，不再支持）

| 旧消息 | 新消息 |
|--------|--------|
| `{ type:'tool_call', name, args }` (CS->SW) | 不再需要，工具由 AI SDK 自动调用 |
| `{ type:'results', payload }` | `{ type:'tool_result', result }` |
| `{ type:'tool_result', success, data, insight }` | 拆分为 `{type:'tool_result'}` + `{type:'insight'}` |
| `{ type:'llm_chat', provider, messages, tools }` | `{type:'chat', messages, conversationId}`（provider 在 SW 内读取） |
| `{ type:'llm_envelope', envelope }` | 直接用 `chunk` / `reasoning` / `done` / `error` |

### 11.2 AI SDK 7.x 事件字段

迁移时注意本地 `ai@7.0.22` 的 `result.stream` 事件字段：
- `text-delta`：`part.text`
- `reasoning-delta`：`part.text`
- `tool-call`：`part.toolCallId`, `part.toolName`, `part.input`（旧版叫 `part.args`）
- `tool-result`：`part.toolCallId`, `part.toolName`, `part.output`（旧版叫 `part.result`）
- `abort`：静默结束
- `tool-error` / `error`：归一化为协议 `error`

`result.fullStream` 在 7.0.22 中仍可用，但已标记 deprecated；新实现和测试统一使用 `result.stream`。
