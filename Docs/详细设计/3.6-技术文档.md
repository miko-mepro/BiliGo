## 一、文档概述

### 1.1 项目背景

BiliGo 是一个 Bilibili 视频智能搜索 Chrome 扩展（MV3），正在从自写 `llm-provider` 架构迁移到 Vercel AI SDK 7.x 架构。本详细设计文档覆盖迁移后的完整实现规范。

- **项目名称**：BiliGo (bili-go)
- **项目类型**：Chrome Extension (Manifest V3)
- **核心功能**：基于 AI 的 Bilibili 视频智能搜索助手
- **技术栈**：Vite 8 + React 19 + TypeScript 6 + Vercel AI SDK 7.x + zod 4.x

### 1.2 文档结构

本详细设计包含 7 个子文档，覆盖接口、协议、算法、状态、UI、综合说明与测试设计：

## 二、系统架构回顾

### 2.1 9 层架构（L0-L8）

详细架构见 `Docs/架构设计/2.2-分层设计.md`，此处仅列概要：

```
L8 设置 UI        L6 UI 外壳
   │ └─────────┐   │
   │           ▼   ▼
   │          L5 UI 内容 ◄── L7 持久化
   │           │
   │           ▼
   │     L4 通信与 Agent 编排 ★
   │        │          │
   │        ▼          ▼
   └─────► L2 配置     L3 工具
              │          │
              └────┬─────┘
                   ▼
              L1 共享基础
```

### 2.2 关键架构变化

| 维度 | 旧版 | 新版（AI SDK） |
|------|------|---------------|
| LLM 通信 | 自写 adapter（1300 行） | @ai-sdk/openai/anthropic/google |
| SSE 解析 | 手写 parseSse（200 行） | AI SDK 内部 |
| 工具调度 | 手写 tool loop（75 行） | `streamText` + `stopWhen: isStepCount(5)` |
| Port 数量 | 双 Port（chat + llm） | 单 Port |
| tool_call 分发 | switch-case 5 个工具 | AI SDK `tools` 参数自动执行 |

### 2.3 数据流（端到端）

```
用户输入
  → ChatInput 捕获
  → 构造 requestMessages（已提交历史 + 新 user，不含 UI 占位消息）
  → dispatch ADD_MESSAGE(user) + SET_LOADING
  → port.postMessage({type:'chat', messages, conversationId})
  → SW 收到
  → validateProviderConfig(provider) + createModel(provider)
  → toModelMessages(messages) + streamText({model, system, messages:modelMessages, tools, stopWhen})
  → result.stream 产出事件
  → SW 推流 Port 消息（chunk/tool_start/videos/insight/done/error）
  → CS 在首个 chunk/reasoning/tool_start 前 ensureAssistantPlaceholder
  → CS dispatch（APPEND_STREAMING/SET_VIDEOS/ADD_UNDERSTANDING/...）
  → ChatState 更新
  → React 重渲染（ChatMessage + VideoCard + AgentInsightCard）
  → 用户看到结果
  → 触发历史保存（防抖 300ms）
```

## 三、核心技术契约汇总

### 3.1 类型契约（3.1 提取）

| 核心类型 | 用途 | 关键字段 |
|---------|------|---------|
| `ChatMessage` | 对话消息 | `role, content, toolCalls?, reasoning?, steps?` |
| `BilibiliVideoCard` | 视频卡片 | `bvid, title, play, duration, pubdate, pic` |
| `ProviderConfig` | Provider 配置 | `id, format, baseUrl, apiKey, model` |
| `SlangUnderstandResult` | 黑话理解输出 | `original, normalized, explanation, matchedDict` |
| `QueryExpandResult` | 查询扩展输出 | `keywords<=8, tags<=5, categories<=3` |
| `RerankResult` | 重排输出 | `items[{bvid,score[0,1]}], strategy, trimmed` |
| `ClarificationRequest` | 澄清输出 | `question, options?, reason` |

### 3.2 协议契约（3.2 提取）

**CS -> SW**：
```typescript
{ type: 'chat'; messages: ChatMessage[]; conversationId: string }
| { type: 'stop' }
| { type: 'ping' }
```

**SW -> CS**：
```typescript
{ type: 'chunk'; delta: string }
| { type: 'reasoning'; delta: string }
| { type: 'tool_start'; toolCallId: string; toolName: string; args: unknown }
| { type: 'tool_result'; toolCallId: string; toolName: string; result: unknown }
| { type: 'videos'; videos: BilibiliVideoCard[] }
| { type: 'insight'; kind: InsightKind; data: unknown }
| { type: 'done' }
| { type: 'error'; message: string; code?: string }
| { type: 'pong' }
```

### 3.3 算法契约（3.3 提取）

**5 步工作流**（由 system prompt 约束，AI SDK 自动执行）：
1. `slang_understand` - 理解黑话（字典优先，未命中调 LLM）
2. `query_expand` - 扩展查询（searchSuggest + searchHot 辅助）
3. `bilibili_search` - 搜索视频（WBI 签名 + SESSDATA）
4. `video_rerank` - 智能重排（fetchVideoTags + LLM 打分）
5. `ask_clarification` - 澄清引导（每会话最多 1 次）

**轮次控制**：`stopWhen: isStepCount(5)`（替代旧版 MAX_TOOL_ROUNDS=5 手写 loop；限制模型 step 数，不等同于工具调用次数）

### 3.4 状态契约（3.4 提取）

**ChatState 19 个 Action**：
- ADD_MESSAGE / SET_LOADING / SET_ERROR / SET_VIDEOS
- APPEND_STREAMING / APPEND_REASONING / CLEAR_STREAMING
- SET_ACTIVITY / ADD_STEP / COMPLETE_STEP / UPDATE_LAST_MESSAGE
- CLEAR_MESSAGES / HYDRATE / REHYDRATE
- ADD_UNDERSTANDING / ADD_EXPANSION / ADD_RERANK
- SET_CLARIFICATION / CLEAR_CLARIFICATION

**10 个不变量**：见 3.4 §10（如 I1: isLoading=true 时必有 activity!=null）

### 3.5 UI 契约（3.5 提取）

**B站粉色设计 Token**：
```typescript
primary: '#FB7299'      // B站粉
primaryDark: '#F25D8E'  // 深粉
bgSoft: '#FFF5F7'       // 浅粉
```

**Panel 尺寸**：min 280x300，8 方向缩放，5px 拖拽阈值

## 四、模块对接矩阵

### 4.1 SW <-> CS 对接

| 对接点 | SW 产出（§3.2） | CS 消费（§3.4） | 类型（§3.1） |
|--------|----------------|----------------|-------------|
| 文本流 | `chunk` | `APPEND_STREAMING` | `delta: string` |
| 推理流 | `reasoning` | `APPEND_REASONING` | `delta: string` |
| 工具开始 | `tool_start` | `SET_ACTIVITY`+`ADD_STEP` | `ToolCall` |
| 工具结果 | `tool_result` | `COMPLETE_STEP` | `toolCallId + unknown result` |
| 视频列表 | `videos` | `SET_VIDEOS` | `BilibiliVideoCard[]` |
| 洞察 | `insight` | `ADD_UNDERSTANDING` 等 | 见 §3.1.13 |
| 完成 | `done` | 复合 dispatch | - |
| 错误 | `error` | `SET_ERROR` | `ErrorPayload` |
| 心跳 | `pong` | 重置超时 | - |

### 4.2 工具 -> Port 消息

| 工具 | tool_result | 额外推送 |
|------|-------------|---------|
| slang_understand | `SlangUnderstandResult` | `insight(understanding)` |
| query_expand | `QueryExpandResult` | `insight(expansion)` |
| bilibili_search | `BilibiliVideoCard[]` | `videos` |
| video_rerank | `RerankResult` | `insight(rerank)` + `videos(重排)` |
| ask_clarification | `ClarificationRequest` | `insight(clarification)` |

### 4.3 AI SDK stream -> Port 映射

| stream 事件 | Port 消息 | 注意 |
|----------------|----------|------|
| `text-delta` | `chunk` | `part.text` |
| `reasoning-delta` | `reasoning` | `part.text` |
| `tool-call` | `tool_start` | `part.toolCallId`, `part.toolName`, `part.input` |
| `tool-result` | `tool_result` | `part.toolCallId`, `part.toolName`, `part.output` |
| `tool-error` | `error` | 工具名上下文 + 错误归一化，随后结束事件循环 |
| `abort` | （不发 error） | 静默结束，随后统一 done |
| `error` | `error` | 归一化后推送，随后结束事件循环 |

## 六、风险与约束

### 6.1 高风险项（必须处理）

| 风险 | 处理时机 | 处理方式 |
|------|---------|---------|
| R1 SW 休眠导致流中断 | L4 | Port 心跳 25s + 断连检测 + 60s 超时 |
| R2 Provider 主机权限不全 | L2 | 补全 9 个域名 + 自定义 origin 按需授权 |

### 6.2 中风险项

| 风险 | 处理方式 |
|------|---------|
| R3 Constructable Stylesheets | M3 先验证 1 个组件 |
| R4 AI SDK SW 兼容性 | M1 最小 streamText 验证 |
| R8 AI SDK 版本变更 | 锁定 ai@7.x，升级前跑测试 |

### 6.3 关键约束

- **AI SDK 7.0.22 事件**：使用 `result.stream`、`reasoning-delta.part.text`、`part.toolCallId/input/output`；`fullStream` 与 `stepCountIs` 仅为 deprecated alias
- **zod 4.x**：`inputSchema`（非旧版 `parameters`）
- **WBI 签名**：不可用 `URLSearchParams.toString()` 替换（编码敏感）
- **Shadow DOM**：`mode: 'open'`（React DevTools 需要）
- **CSP**：content script 不允许 eval/动态 import

| 里程碑 | 详细设计章节 | 验证标准 |

**SW 端开发顺序**：
1. `config/provider-factory.ts` - createModel
2. `background/port-protocol.ts` - 消息类型定义
3. `background/stream.ts` - streamText + `result.stream` 推流
4. `background/index.ts` - Port 监听
5. `tools/*.ts` - 5 个工具的 tool() 定义

**CS 端开发顺序**：
1. `content/port-connection.ts` - Port 通信 + 消息消费
2. `content/chat-context.tsx` - reducer + state
3. `components/MessageList.tsx` + `ChatMessage.tsx` - 消息渲染
4. `components/VideoCard.tsx` + `FilterSortControls.tsx` - 视频展示
