# 3.7 核心逻辑测试设计

> 范围：BiliGo 迁移到 Vercel AI SDK 7.x 后的核心逻辑单元测试
> 基线：本地 `ai@7.0.22`、Vitest、jsdom
> 不包含：UI 组件渲染测试、视觉测试、E2E

---

## 1. 测试目标与修订后契约

本测试设计覆盖 7 个测试文件，验证 3.6 §8 中与本次迁移直接相关的通信、流式事件、工具领域逻辑、状态机、Provider 工厂和错误协议。

实现和测试统一使用以下已核对本地类型的 AI SDK 7.0.22 契约：

- `stopWhen: isStepCount(5)`；`stepCountIs` 仅为 deprecated alias
- 遍历 `result.stream`；`result.fullStream` 仅为 deprecated alias
- 文本增量：`{ type:'text-delta', text }`
- 推理增量：`{ type:'reasoning-delta', text }`
- 工具调用：`part.toolCallId` / `part.toolName` / `part.input`
- 工具结果：`part.toolCallId` / `part.toolName` / `part.output`
- 用户中断可能表现为 `abort` part，也可能在迭代过程中抛出 `AbortError`

ChatState 使用 19 个 Action。发送请求时只提交已完成历史和新 user；首个 `chunk` / `reasoning` / `tool_start` 到达时创建空 assistant 占位消息。工具步骤写入该 assistant，收到 `done` 后使用 `UPDATE_LAST_MESSAGE` 提交流式正文。

---

## 2. 全局测试约定

沿用旧仓库 `Backend/BiliAgent/packages/extension/` 的测试习惯：

- 测试框架：`vitest`，`environment: 'jsdom'`
- setup：`test/setup.ts` 全局 mock `chrome.runtime/storage/cookies/tabs`
- 模块级 mock：`vi.hoisted()` + `vi.mock()`
- Port helper：`createPort(name)` + `emitMessage()` + `emitDisconnect()` + `waitForPostMessages()`
- 工具逻辑：mock `callLlmForJson`，测试领域结果和 memoryStore 更新
- reducer：直接调用 `chatReducer(state, action)`，不渲染 React
- 时间字段：`vi.useFakeTimers()` + `vi.setSystemTime()`
- 每个测试前执行 `vi.clearAllMocks()`；需要重置实现时使用 `mockReset()`

CI 除 Vitest 外必须执行 TypeScript typecheck。完整 mock `ai` 会掩盖真实 SDK 导出变化，typecheck 是 R8 版本漂移的必要防线。
