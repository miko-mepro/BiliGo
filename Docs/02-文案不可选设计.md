# 02 - 文案不可选设计

## 1. 背景与问题

面板内存在三类纯展示文案，在日常使用中被鼠标拖选时会形成"选中蓝底"视觉污染，影响整洁度与品牌一致性：

- **BiliGo 品牌标题**：`Panel.tsx` header 内 SVG `<text>` 渲染的 "BiliGo"
- **空态主标题**："搜索你想看的视频..."（`MessageList.tsx` 空态 + `ChatInput.tsx` placeholder 默认值）
- **空态副提示**："我是你的B站AI助手，可以帮你搜索视频、总结内容、推荐内容等。"

这些文本均为不可交互的装饰/提示信息，无需被选中复制，应设计为不可选。

## 2. 适用范围

仅针对以下 3 处文本节点，不扩展到消息气泡、视频卡片标题等可能需要复制的内容区域：

| # | 文本 | 所在文件 | 渲染位置 | 当前 class |
|---|------|---------|---------|-----------|
| 1 | `BiliGo`（SVG text） | `Main/src/components/Panel.tsx:513` | header 标题 | `.bili-agent-panel__title` 内的 `svg > text` |
| 2 | `搜索你想看的视频...`（空态主标题） | `Main/src/components/MessageList.tsx:138` | 消息列表空态 | `.bili-agent-message-list__empty-text` |
| 3 | `我是你的B站AI助手...`（空态副提示） | `Main/src/components/MessageList.tsx:140` | 消息列表空态 | `.bili-agent-message-list__empty-hint` |

> 注：`ChatInput.tsx:8` 的 `placeholder` 默认值同为该文案，但 placeholder 本身由浏览器原生渲染、不可被选中，无需处理；测试文件 `MessageList.test.tsx:255` 仅断言文案内容、不涉及选择行为，无需改动。

## 3. 方案对比

### 方案 A：纯 CSS（✅ 采用）

在 `Main/src/content/styles.ts` 中为上述 3 个 class 追加 `user-select` 规则，并加 WebKit/Firefox 前缀以兼容旧内核：

```css
.bili-agent-panel__title {
  /* ...既有规则... */
  -webkit-user-select: none;
  -moz-user-select: none;
  user-select: none;
}

.bili-agent-message-list__empty-text {
  /* ...既有规则... */
  -webkit-user-select: none;
  -moz-user-select: none;
  user-select: none;
}

.bili-agent-message-list__empty-hint {
  /* ...既有规则... */
  -webkit-user-select: none;
  -moz-user-select: none;
  user-select: none;
}
```

为兜底部分浏览器对 SVG `<text>` 的独立选择行为，再给 `.bili-agent-panel__title svg` 与 `.bili-agent-panel__title text` 显式加同款规则。

**优点**
- 与项目既有约定一致：`.bili-agent-panel__search` 已使用同样的 `user-select: none` 写法，风格统一
- 零侵入：不触碰任何组件 JSX 逻辑，无运行时开销、无 JS 回归风险
- 可逆：未来若需允许复制，删除该行即可
- 覆盖完整：含 `-webkit-` / `-moz-` 前缀，兼容旧 Edge/Chrome/Firefox

**缺点**
- 无

### 方案 B：SVG 加 `pointer-events="none"`（弃用）

在方案 A 基础上额外给标题 SVG 加 `pointer-events="none"`。

**弃用原因**：可能影响 `aria-label="BiliGo"` 在部分屏幕阅读器下的可达性语义；当前 SVG 仅作装饰无点击交互，收益边际但引入无障碍风险，超出"不可选"范围，性价比低。

### 方案 C：inline style（弃用）

在 JSX 里给三处元素直接加 `style={{ userSelect: 'none' }}`。

**弃用原因**：与项目约定不符——样式统一集中在 `styles.ts`（见 `.bili-agent-panel__search` 等既有规则），inline style 破坏一致性，且需补 webkit/moz 前缀时写法更冗长。

## 4. 实施改动点

| 文件 | 改动 |
|------|------|
| `Main/src/content/styles.ts` | `.bili-agent-panel__title`、`.bili-agent-message-list__empty-text`、`.bili-agent-message-list__empty-hint` 各加 3 行 `user-select` 规则；新增 `.bili-agent-panel__title svg` 与 `.bili-agent-panel__title text` 两条规则各加 3 行 |

总改动：3 条既有规则各 +3 行，新增 2 条规则各 +4 行（含选择器），约 17 行。

## 5. 验证

- 视觉验证：打开面板，对 3 处文案分别尝试鼠标拖选，应无蓝底高亮
- 回归验证：消息气泡正文、视频卡片标题仍可被选中复制（未被波及）
- 现有测试不受影响（`MessageList.test.tsx:255` 仅断言文本存在，不涉及选择行为）

## 6. 风险与回滚

- **风险**：低。CSS-only，不动逻辑
- **回滚**：删除新增的 `user-select` 规则即可
