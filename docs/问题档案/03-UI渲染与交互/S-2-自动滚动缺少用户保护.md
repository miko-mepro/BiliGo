# S-2 自动滚动缺少用户保护

## 基本信息
- **严重程度**: HIGH
- **问题类型**: UI渲染/自动滚动
- **确认状态**: 已确认
- **来源文档**: 搜索结果展示与重排问题记录.md
- **发现日期**: 2026-08-01
- **关联问题**: S-1

## 问题描述
MessageList 使用 useEffect 监听流式文本、推理文本、render item 数量和视频数组，这些依赖任一变化都会无条件调用 `scrollIntoView({ behavior: 'smooth' })`。

## 代码位置
- `Main/src/components/MessageList.tsx:93-96`

## 根因分析
问题的核心在于自动滚动 effect 缺少"用户正在阅读"的保护条件，且依赖项覆盖了所有高频更新源。

**effect 依赖与触发时机**（MessageList.tsx:93-96）：
```typescript
useEffect(() => {
  endRef.current?.scrollIntoView({ behavior: 'smooth' });
}, [renderItems.length, state.streamingContent, state.streamingReasoning, videos]);
```

四类依赖触发时机：
- `renderItems.length`：新消息或新 insight 进入合并列表 -> 滚动到底部
- `state.streamingContent`：每个流式文本 chunk 更新 -> 高频滚动
- `state.streamingReasoning`：推理文本更新 -> 高频滚动
- `videos`：Search 或 rerank 推送新数组 -> 滚动到底部

**派发路径证据**：
- chat-context.tsx:395-403 证明 chunk 和 reasoning 会分别派发 `APPEND_STREAMING`、`APPEND_REASONING`
- chat-context.tsx:428-432 证明视频消息会派发 `SET_VIDEOS`

因此，用户在流式输出期间手动上拉时，只要继续收到 chunk、reasoning 或视频数组更新，就会再次触发滚动。

**缺失的保护机制**：
当前 MessageList 没有发现以下任何机制：
- 监听滚动容器并判断用户是否接近底部
- `isAtBottom`、`userScrolled` 或类似状态
- 用户主动上拉后暂停自动滚动的标记
- 仅在新消息到达且用户已经位于底部时滚动的条件判断

**insight 卡片的局部状态**：insight 卡片的 `isExpanded` 是局部状态，展开/收起本身不在 effect 依赖中，但如果展开期间又有流式状态更新（chunk、reasoning），后续依赖变化仍会把视图拉到底部，打断用户的展开阅读。

## 影响范围
- **用户体验影响**：
  - 用户无法在流式输出期间稳定阅读历史内容，手动上拉会被高频的 chunk/reasoning 更新反复拉回底部
  - 展开 insight 卡片阅读详情时，若流式输出未结束，视图会被强行拉走
  - 在搜索场景下，videos 数组的更新（尤其 rerank 的二次推送）会触发额外滚动
  - 这是一个持续性的交互干扰，影响所有流式对话场景，不限于搜索
- **技术债务影响**：
  - 自动滚动逻辑与流式状态派发紧耦合，缺少抽象的"滚动意图"管理
  - effect 依赖中包含 `state.streamingContent` 和 `state.streamingReasoning` 这类高频变化值，是性能与交互的双重隐患
  - 缺少用户交互状态（滚动位置、手动滚动标记）的收集，导致后续任何依赖"用户阅读位置"的功能都无法实现
- **与其他问题的关联**：
  - 与 S-1 关联：S-1 中描述的"搜索辅助内容即时展示"会产生多次 videos 和 insight 更新，每一次更新都会触发本问题的自动滚动，两者叠加会显著放大交互干扰

## 复现路径（如有）
1. 发起一次流式对话（包含文本或推理输出）
2. 在流式输出进行中，手动向上滚动到历史内容
3. 继续观察：当下一个 chunk 或 reasoning 更新到达时
4. 预期结果：视图会被自动滚动拉回底部，打断阅读
5. 变体：展开一个 insight 卡片，在流式输出未结束时阅读详情，观察视图是否被拉走

## 待验证假设（如有）
- 假设1：`behavior: 'smooth'` 的滚动动画与高频 chunk 更新叠加时，可能产生动画队列堆积或视觉抖动（需运行时录制确认）
- 假设2：rerank 的二次 videos 推送触发的滚动，可能与首次 videos 推送的滚动动画尚未完成时叠加，导致跳动

## 建议的修复方向
实现"用户正在阅读"保护机制：
1. **监听滚动容器位置**：在滚动容器的 onScroll 中计算用户是否接近底部（如距离底部 < 阈值像素）。
2. **引入 isAtBottom / userScrolled 状态**：当用户主动上拉超过阈值时，设置 `userScrolled = true`，暂停自动滚动。
3. **条件化滚动触发**：effect 中仅当 `isAtBottom === true` 时才调用 `scrollIntoView`。
4. **恢复机制**：当用户重新滚动到底部时，清除 `userScrolled` 标记，恢复自动滚动。
5. **新消息特殊处理**：对于真正的新消息（renderItems.length 增加），可考虑即使用户上拉也给予轻微提示（如未读标记），而不是强行拉回。
6. **高频依赖优化**：将 `state.streamingContent` 和 `state.streamingReasoning` 从 effect 依赖中移除或降频，改为基于 isAtBottom 的内部节流滚动。
