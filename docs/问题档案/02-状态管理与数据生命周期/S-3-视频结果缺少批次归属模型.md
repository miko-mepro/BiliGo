# [S-3] 视频结果缺少批次归属模型

## 基本信息
- **严重程度**: HIGH
- **问题类型**: 状态管理 / 数据生命周期
- **确认状态**: 已确认
- **来源文档**: 搜索结果展示与重排问题记录.md
- **发现日期**: 2026-08-01
- **关联问题**: S-1, S-4, R-1

## 问题描述
`SET_VIDEOS` 直接替换 `state.videos`，视频网格又在全部消息和 insight 渲染完成后统一放置，因此旧视频不会留在旧输出下。协议中的 `videos` 消息没有批次或消息关联字段。`ChatState` 只有 `videos: BilibiliVideoCard[]`，没有 search/batch 标识。

这导致新搜索会顶掉旧视频卡片，用户期望的"旧卡片留在旧输出下、新卡片留在新输出下"无法实现。

## 代码位置
- `Main/src/content/chat-context.tsx:166-179`（SET_VIDEOS 直接替换 state.videos）
- `Main/src/content/chat-context.tsx:428-432`（视频网格在消息与 insight 渲染完成后统一放置）
- `Main/src/components/MessageList.tsx:144-195`（消息渲染时引用全局 videos）

## 根因分析
视频结果的状态模型缺少批次归属信息，是单一全局数组：

```ts
// chat-context.tsx 关键逻辑示意
interface ChatState {
  videos: BilibiliVideoCard[];  // 无 searchId/batchId/messageId/anchorId
}

// SET_VIDEOS 处理
case 'SET_VIDEOS':
  return { ...state, videos: action.videos };  // 直接替换，旧数据丢失
```

由于状态只保存"最新一组视频"，任何新搜索都会通过 `SET_VIDEOS` 顶掉前一组。而视频网格的渲染时机又依赖全部消息与 insight 渲染完成后的统一放置，进一步加剧了"旧视频不留在旧输出下"的现象。

协议层的 `videos` 消息同样缺少批次或消息关联字段，无法在状态层重建归属关系。因此 `ChatState` 无法知道"这组视频属于哪一次搜索、哪一条消息"。

这种状态设计直接导致：
1. 旧视频不会留在旧输出下，被新搜索直接顶掉。
2. 旧 insight 可能继续出现在消息流中，而视频网格已经只剩最新一组视频，产生语义错配。

## 影响范围
- **用户体验影响**：新搜索会顶掉旧视频卡片，用户希望旧卡片留在旧输出下、新卡片留在新输出下无法实现。旧 insight 可能继续出现在消息流中，而视频网格已经只剩最新一组视频，产生语义错配，用户难以将旧 insight 与对应视频对应起来。
- **技术债务影响**：视频状态缺少归属模型是状态层与渲染层错配的根因。任何涉及视频与消息关联的新需求（如"在某条消息下展开该次搜索的视频"）都需要先补齐归属模型。
- **与其他问题的关联**：与 S-1、S-4 共享"视频展示与重排"问题族；与 R-1（历史标题类型校验缺失）共享"状态数据缺少字段级校验"的潜在风险--若未来引入批次字段但缺少校验，可能再次出现 R-1 类的 render crash。

## 复现路径（如有）
1. 发起第一次搜索，等待视频卡片渲染。
2. 在同一会话发起第二次搜索。
3. 观察第一次的视频卡片是否被顶掉，且旧输出下不再保留对应视频。
4. 观察 insight 是否仍留在消息流中，导致旧 insight 与新视频语义错配。

## 待验证假设（如有）
- 假设1：用户期望"旧卡片留在旧输出下"实际包含两层诉求--状态层保留多组视频，渲染层将视频绑定到对应消息。需要确认用户是否接受"旧视频以折叠形式留在旧输出下"。
- 假设2：引入批次模型后，旧 insight 与视频的语义错配可由渲染层按 anchorId 自动对齐消除。需要确认 insight 是否已携带可关联到搜索批次的字段。

## 建议的修复方向
引入搜索批次模型（searchId/batchId/messageId/anchorId），将视频数组与具体消息关联，支持多次搜索结果并存：

1. 扩展 `ChatState`，将 `videos: BilibiliVideoCard[]` 升级为带归属信息的结构，例如 `videoBatches: VideoBatch[]`，每个 batch 携带 searchId、messageId、anchorId 与对应视频数组。
2. 扩展协议层 `videos` 消息，增加批次或消息关联字段，使状态层能重建归属关系。
3. 调整 `SET_VIDEOS` 为追加/更新对应批次，而非直接替换全局数组。
4. 调整视频网格渲染逻辑，按 anchorId 将视频绑定到对应消息位置，使旧视频留在旧输出下。
5. 在引入批次字段时同步加入字段级校验（参考 R-1 的教训），避免新字段再次出现类型缺失导致的 render crash。

修复仅描述思路，不包含具体实现代码。
