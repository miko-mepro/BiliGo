# [R-2] 历史重命名异步竞态

## 基本信息
- **严重程度**: MEDIUM
- **问题类型**: 异步竞态 / 状态过期
- **确认状态**: 高风险待验证，尚无运行时堆栈证明直接导致 render crash
- **来源文档**: 渲染崩溃问题记录.md
- **发现日期**: 2026-08-01
- **关联问题**: R-3

## 问题描述
`handleRenameConfirm` 在 `await onRename(id, newTitle)` 返回后才执行 `setRecords`，并在 `finally` 中执行 `setEditing(null)`。Panel 在切换到设置视图时不再渲染 `HistoryDropdown`。

若在 `onRename` 尚未返回时点击设置按钮，`HistoryDropdown` 卸载，异步操作返回后旧闭包仍执行状态更新和 ref 写入。

## 代码位置
- `Main/src/components/HistoryDropdown.tsx:172-194`（handleRenameConfirm 的 await/setRecords/finally 逻辑）
- `Main/src/components/Panel.tsx:608-631`（切换到设置视图时不再渲染 HistoryDropdown）

## 根因分析
重命名确认流程是异步的，但卸载与异步完成之间存在竞态窗口：

```ts
// HistoryDropdown.tsx 关键逻辑示意
const handleRenameConfirm = async (id, newTitle) => {
  await onRename(id, newTitle);  // 异步等待，期间组件可能已卸载
  setRecords(prev => prev.map(r => r.id === id ? { ...r, title: newTitle } : r));
  // finally 中 setEditing(null)
};
```

当用户在 `onRename` 尚未返回时点击设置按钮，`Panel` 切换到设置视图，`HistoryDropdown` 不再渲染，组件卸载。此时异步操作仍在进行，待其 resolve 后，旧闭包会继续执行 `setRecords` 与 `setEditing`。

React 在较新版本中通常会忽略已卸载组件的 `setState`，但 ref 写入与闭包内的状态更新仍属于"卸载后的副作用"，存在状态过期或无效更新风险。需要强调：当前并没有运行时堆栈证明此处必然触发 render crash。

## 影响范围
- **用户体验影响**：产生过期结果或卸载后的状态更新风险。当前 React 运行时通常会忽略卸载组件的 setState，并没有证据表明此处必然触发 render crash。用户在快速切换视图时可能感知到历史列表状态短暂不一致，但不一定崩溃。
- **技术债务影响**：异步操作缺少取消机制是 React 异步竞态债务的典型表现。后续若 `setRecords` 逻辑变重或闭包持有更多引用，过期更新的风险会上升。
- **与其他问题的关联**：与 R-3（连接测试结果过期覆盖）共享"异步竞态/状态过期"问题族，二者机制类似--都在异步返回后对可能已卸载或已切换的组件执行状态更新。

## 复现路径（如有）
1. 在历史下拉中对某条历史记录触发重命名并确认。
2. 在 `onRename` 尚未返回时，立即点击设置按钮切换到设置视图。
3. 观察 `HistoryDropdown` 卸载后，异步返回时是否仍执行 `setRecords` / `setEditing`。
4. 切回聊天视图，观察历史列表状态是否一致。

## 待验证假设（如有）
- 假设1：用户报告的 render crash 由该竞态路径触发，但需要运行时堆栈证明。当前仅静态确认存在竞态窗口，未确认崩溃结果。
- 假设2：React 当前版本对卸载后 setState 的忽略行为掩盖了该问题，但 ref 写入未被忽略，可能在特定时序下造成状态不一致。需要确认 ref 写入的具体影响。

## 建议的修复方向
在组件卸载或视图切换时取消未完成的异步操作（AbortController 或 isMounted 标志）：

1. 在 `HistoryDropdown` 中引入 `isMountedRef` 或 `AbortController`，在卸载时标记取消，异步返回后检查标志再执行 `setRecords` / `setEditing`。
2. 或在 `Panel` 切换视图时，统一通知子组件取消未完成的异步操作，而非依赖组件自行处理。
3. 修复后需确认重命名后切换视图不再产生过期状态更新，且历史列表在切回后状态一致。
4. 评估是否将重命名流程改为由 `Panel` 统一管理状态，避免 `HistoryDropdown` 卸载后仍持有状态更新闭包。

修复仅描述思路，不包含具体实现代码。
