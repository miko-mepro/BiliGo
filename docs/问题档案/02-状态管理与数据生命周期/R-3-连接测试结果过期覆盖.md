# [R-3] 连接测试结果过期覆盖

## 基本信息
- **严重程度**: MEDIUM
- **问题类型**: 异步竞态 / 状态过期
- **确认状态**: 高风险待验证，尚无运行时堆栈证明直接导致 render crash
- **来源文档**: 渲染崩溃问题记录.md
- **发现日期**: 2026-08-01
- **关联问题**: R-2, N-3

## 问题描述
连接测试使用 `Promise.race` 等待 service worker 响应或 12 秒超时。Provider 变化或组件卸载时，现有 cleanup 只移除 listener 和 timer，没有取消已经创建的 Promise。

若用户在等待期间切换 Provider 或离开设置页，旧请求仍可能在完成并调用 `setStatus`、`setErrorMessage`、`setIsTimeout`。

## 代码位置
- `Main/src/components/model-settings/TestConnectionButton.tsx:115-189`（Promise.race 等待响应或 12 秒超时，cleanup 未取消 Promise）

## 根因分析
连接测试的等待逻辑基于 `Promise.race`，但 cleanup 只清理了同步资源：

```ts
// TestConnectionButton.tsx 关键逻辑示意
const result = await Promise.race([
  waitForServiceWorkerResponse(),
  new Promise((_, reject) => setTimeout(() => reject('timeout'), 12000)),
]);

// cleanup（Provider 变化或卸载时）
// 仅移除 listener 和 timer，未取消已经创建的 Promise
```

当用户在等待期间切换 Provider 或离开设置页，组件 cleanup 会移除 `onMessage` 的 listener 和超时 timer，但已经创建的 `Promise.race` 本身无法被取消。旧请求在 service worker 端仍在执行，待其返回后，旧 Promise 的 then 分支仍会调用 `setStatus`、`setErrorMessage`、`setIsTimeout`。

这就产生两类过期覆盖风险：

1. **Provider 切换**：旧 Provider 的结果可能覆盖新 Provider 的 UI 状态，用户看到的是上一个 Provider 的测试结果而非当前。
2. **视图切换/卸载**：组件卸载后仍执行状态更新，产生无效状态更新。

需要强调：尚无运行时堆栈证明该路径直接导致 render crash。

## 影响范围
- **用户体验影响**：旧 Provider 的结果可能覆盖新 Provider 的 UI 状态，或者在视图切换后产生无效状态更新。用户在快速切换 Provider 时可能看到状态闪烁或与当前 Provider 不一致的结果，但不一定崩溃。
- **技术债务影响**：`Promise.race` 缺少取消机制是异步竞态债务的典型表现。cleanup 只清理同步资源（listener、timer），未覆盖异步资源（Promise），形成半截子清理。
- **与其他问题的关联**：与 R-2（历史重命名异步竞态）共享"异步竞态/状态过期"问题族；与 N-3（设置 Port 无断线检测）共同构成设置页的断线/竞态问题族，二者机制互补--N-3 解决通道断开反馈，R-3 解决请求结果过期覆盖。

## 复现路径（如有）
1. 在设置页对 Provider A 发起连接测试。
2. 在等待响应期间（未返回前），立即切换到 Provider B。
3. 观察 Provider A 的响应返回后，是否覆盖 Provider B 的 UI 状态。
4. 或在等待期间离开设置页，观察组件卸载后是否仍执行 `setStatus` 等调用。

## 待验证假设（如有）
- 假设1：用户报告的 render crash 由该过期覆盖路径触发，但需要运行时堆栈证明。当前仅静态确认存在过期更新窗口，未确认崩溃结果。
- 假设2：旧 Provider 的结果覆盖新 Provider 状态时，因状态形态不匹配（例如错误类型与当前 Provider 不符）触发异常。需要确认 `setStatus` / `setErrorMessage` 接收的参数形态是否与 Provider 强相关。

## 建议的修复方向
引入请求取消机制，在 Provider 变化或组件卸载时取消未完成的 `Promise.race`：

1. 在 `TestConnectionButton` 中为每次连接测试分配唯一请求 ID 或 `AbortController`，在 cleanup 时标记取消，异步返回后检查标志再执行 `setStatus` / `setErrorMessage` / `setIsTimeout`。
2. 或将 `Promise.race` 中超时 Promise 与 service worker 响应 Promise 统一接入 `AbortSignal`，在 cleanup 时 `controller.abort()`，使 Promise 主动 reject 而非继续 pending。
3. 修复后需确认 Provider 切换时旧结果不再覆盖新状态，且卸载后不再产生无效状态更新。
4. 评估是否需要将连接测试状态提升到父组件统一管理，避免子组件卸载后仍持有状态更新闭包。
5. 与 N-3 的 `onDisconnect` 修复保持协同，避免重复实现取消机制。

修复仅描述思路，不包含具体实现代码。
