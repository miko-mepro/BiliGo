# [R-1] 历史标题类型校验缺失

## 基本信息
- **严重程度**: CRITICAL
- **问题类型**: 渲染异常 / 类型校验缺失
- **确认状态**: 唯一已确认 render crash 入口；触发来源待确认
- **来源文档**: 渲染崩溃问题记录.md
- **发现日期**: 2026-08-01
- **关联问题**: S-3

## 问题描述
搜索过滤调用 `r.title.toLowerCase()`，但历史索引存储只校验数组，不校验元素字段类型。若历史索引中存在 `title: null`、数字、对象或缺失字段，render 会抛出 `TypeError`。

这是当前唯一通过静态代码审查确认的"render 阶段直接抛异常"路径。

## 代码位置
- `Main/src/components/HistoryDropdown.tsx:214-219`（搜索过滤调用 r.title.toLowerCase()）
- `Main/src/lib/history/store.ts:59-65`（历史索引存储只校验数组，不校验元素字段类型）
- `Main/src/lib/history/sync.ts:52-56`（同步路径同样缺少字段级校验）

## 根因分析
历史索引的持久化校验只检查"是不是数组"，不检查数组元素的内部字段类型：

```ts
// history/store.ts 关键逻辑示意
const raw = JSON.parse(stored);
if (Array.isArray(raw)) {
  records = raw;  // 只校验数组形态，未校验元素 title 类型
}
```

而渲染层的搜索过滤直接调用字符串方法：

```ts
// HistoryDropdown.tsx 关键逻辑示意
const filtered = records.filter(r => r.title.toLowerCase().includes(keyword));
//                       ^^^ r.title 可能为 null/number/object/undefined
```

当 `r.title` 不是字符串时，`.toLowerCase()` 会抛出 `TypeError: Cannot read properties of null (reading 'toLowerCase')` 之类的异常。该异常发生在 React render 阶段，会被 `ErrorBoundary` 捕获，但 `ErrorBoundary` 只能展示降级 UI，不能修复底层数据。

因此，只要历史索引中存在一条 `title` 非字符串的记录，并且用户在"搜索历史记录"输入框输入了非空字符，就会稳定触发 render crash。

存储路径缺少字段级校验是根因。`sync.ts` 的同步路径同样未校验，意味着外部写入的脏数据可能通过同步进入本地索引。

## 影响范围
- **用户体验影响**：当前唯一通过静态代码审查确认的"render 阶段直接抛异常"路径。`ErrorBoundary` 可以捕获但不会修复数据，用户会看到错误边界 UI，且每次在搜索框输入都会重现，除非清除历史索引。
- **技术债务影响**：历史索引的持久化层缺少字段级校验是数据信任债务的典型表现--状态层假设数据可信，但数据来源（用户历史、外部同步）不保证类型。未来若新增字段，同样可能因校验缺失再次触发 render crash。
- **与其他问题的关联**：与 S-3（视频结果缺少批次归属模型）共享"状态数据缺少字段级校验"的潜在风险--若未来引入批次字段但缺少校验，可能再次出现 R-1 类的 render crash。与按钮快速点击现象的关系未确认。

## 复现路径（如有）
1. 让 `bili-agent-history-index` 存在数组元素，但至少一条记录 `title` 不是字符串（例如 `null`、数字或对象）。
2. 打开面板展开历史下拉。
3. 在"搜索历史记录"输入框输入至少一个非空字符。
4. 观察控制台 `TypeError` 和错误边界 UI。

## 待验证假设（如有）
- 假设1：用户实际遇到的 render crash 由历史索引中存在非字符串 title 的脏数据触发。需要从用户环境导出 `bili-agent-history-index` 检查是否存在非字符串 title。
- 假设2：脏数据来源是某次历史重命名或同步写入时未校验字段类型。需要审计历史写入路径确认脏数据来源。
- 假设3：用户报告的"按钮快速点击导致崩溃"与该 render crash 存在关联，可能因为快速点击触发了历史下拉展开与搜索输入叠加，导致脏数据路径被命中。需要确认按钮快速点击现象与该路径是否耦合。

## 建议的修复方向
在 `history/store.ts` 和 `sync.ts` 添加逐条字段校验（id, title, 时间字段）；在 `HistoryDropdown` 搜索过滤前添加类型保护：

1. 在 `history/store.ts` 的加载路径增加逐条字段校验，过滤掉 `title` 非字符串、`id` 缺失、时间字段非法的记录，或对缺失字段做安全降级（如 `title ?? ''`）。
2. 在 `history/sync.ts` 的同步写入路径同样校验字段类型，阻止外部脏数据进入本地索引。
3. 在 `HistoryDropdown` 的搜索过滤前增加类型保护，例如 `typeof r.title === 'string' ? r.title.toLowerCase() : ''`，作为 render 层的防御性兜底。
4. 修复后需验证历史下拉在脏数据存在时不再 render crash，且脏数据被持久化层清理或降级。
5. 评估是否需要在加载时清理已存在的脏数据，避免历史遗留脏数据持续触发防御逻辑。

修复仅描述思路，不包含具体实现代码。
