# 阶段3 中优先级修复

## 阶段目标

收敛中优先级的用户体验和错误诊断能力问题。本阶段聚焦 6 个 MEDIUM 级别问题：N-1 错误分类粗粒度、N-3 设置 Port 断线检测、N-4 工具网络失败语义、S-1 搜索辅助内容即时展示、R-2 历史重命名异步竞态、R-3 连接测试结果过期覆盖。这些问题已确认代码缺陷，但部分触发场景需运行时证据确认。

## 包含方案

### N-1 连接测试错误分类粗粒度，文案无法区分根因

- 严重程度：MEDIUM
- 问题档案：`docs/问题档案/01-网络与超时控制/N-1-连接测试错误分类粗粒度.md`
- 涉及代码：
  - `Main/src/background/port-protocol.ts:96-132`（`inferErrorCode` 将未识别异常统一归类为 `NETWORK_ERROR`）
  - `Main/src/background/stream.ts`（连接测试路由）
- 修复目标：统一网络错误分类语义，区分 DNS 错误、TLS 错误、HTTP 状态码错误、超时和 Provider 配置错误，使 UI 文案能提示用户应检查网络、API Key、Base URL 还是模型名。
- 关键约束：N-1 是 N-4 的前置依赖，N-4 需接入 N-1 定义的统一错误分类。
- 测试策略：单元测试覆盖各类网络异常的分类路径和对应文案。
- 验收标准：不同根因的网络异常显示不同文案，用户能从文案推断应检查哪个环节。
- 运行时验证：N-V2 假设（错误发生在 DNS、TLS、代理、CORS/权限、HTTP 状态码还是请求超时）需在阶段0 完成后采集 DevTools Network 证据。

### N-3 设置页 Port 未注册断线处理，缺少心跳机制

- 严重程度：MEDIUM
- 问题档案：`docs/问题档案/01-网络与超时控制/N-3-设置Port无断线检测.md`
- 涉及代码：
  - `Main/src/components/Panel.tsx:425-445`（设置 Port 只建立和销毁）
  - `Main/src/components/model-settings/TestConnectionButton.tsx:115-189`（只注册 `onMessage`，未注册 `port.onDisconnect`，无心跳）
- 修复目标：为设置 Port 注册 `onDisconnect` 处理，统一两条 Port 链路的断线检测能力，使设置 Port 在请求发送后断开时能及时感知，不再只依赖 12 秒兜底超时。
- 关键约束：N-3 与 R-3 共用 `TestConnectionButton` 状态管理，修复时需统一检查 listener、timer、取消和过期结果。
- 测试策略：单元测试覆盖 Port 断线后的状态清理和用户反馈。
- 验收标准：设置 Port 断线时前端及时感知并给出反馈，与聊天 Port 的断线检测能力一致。
- 运行时验证：N-V4 假设（用户点击"测试连接"时设置 Port 是否已断开）需在阶段0 完成后采集 service worker 控制台的 `onDisconnect` 时间证据。

### N-4 Bilibili 工具网络失败语义与连接测试不一致

- 严重程度：MEDIUM
- 问题档案：`docs/问题档案/01-网络与超时控制/N-4-Bilibili工具网络失败语义不一致.md`

- 验收标准：Bilibili 工具网络失败显示与连接测试语义一致的文案，用户能区分网络问题与搜索无结果。
- 运行时验证：N-V1 假设（具体是哪个 Provider、哪个 URL 或哪个模型请求失败）需在阶段0 完成后采集非敏感信息。

### R-2 历史重命名异步竞态，结果可能晚于视图卸载

- 严重程度：MEDIUM
- 问题档案：`docs/问题档案/02-状态管理与数据生命周期/R-2-历史重命名异步竞态.md`
- 涉及代码：

- 验收标准：历史重命名在视图切换后不再写入过期状态。
- 运行时验证：依赖阶段0 恢复 E2E 后补充渲染堆栈验证。

- **建议依赖**：阶段2 收敛。阶段2 处理的 HIGH 级别问题应优先收敛，避免阶段3 的修复与阶段2 产生冲突。

- **因果链回查**：S-1 是 S-2/S-3/S-4 因果链上游，归入阶段3。修复 S-1 时需回查阶段2 的 S-2/S-3/S-4 修复是否仍成立。

## 风险

- **N-1 错误分类需覆盖多种网络异常**：DNS 错误、TLS 错误、HTTP 状态码错误、超时和 Provider 配置错误的区分需要准确的异常类型识别。若分类过于细化可能增加维护成本，若过于粗粒度则无法解决文案无法区分根因的问题。
- **N-3 与 R-3 共用代码修改风险**：两者共同涉及 `TestConnectionButton.tsx:115-189`，分别修改可能引入状态管理冲突。建议由同一修复批次统一推进，避免分别修改造成二次竞态。
- **S-1 回查阶段2 的返工风险**：S-1 是 S-2/S-3/S-4 因果链上游，修复 S-1 可能改变阶段2 修复的前提假设。若 S-1 延迟展示辅助内容，S-2 的滚动频率、S-3 的批次模型设计、S-4 的排序覆盖行为可能需要重新评估。
- **N-4 依赖 N-1 的串行延迟**：N-4 必须等待 N-1 完成，可能延长阶段3 整体周期。建议 N-1 优先推进，N-4 的技术方案设计并行进行。
- **R-2/R-3 取消机制可能与 React 18 并发渲染交互**：`AbortController` 和 `cancelled` 标志在 React 18 并发渲染下可能存在边缘情况，需确认取消机制在严格模式双调用下仍正确工作。
- **N-3 断线检测可能增加 service worker 负担**：为设置 Port 增加心跳机制可能增加 service worker 的消息频率，需评估对性能的影响。
