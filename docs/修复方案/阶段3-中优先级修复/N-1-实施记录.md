## 实际改动

### `Main/src/background/port-protocol.ts`

- `inferErrorCode(error: unknown)` 入参由 `string` 扩展为 `unknown`，调用点不再提前拍平为字符串，保留原始错误结构用于分类。
- 支持错误链：最多遍历 2 层 `cause`，避免深度过长或循环引用导致分类失败。
- 新增结构化字段分类（`code`/`errno`）：
  - `ENOTFOUND`、`EAI_AGAIN` → `DNS_ERROR`
  - `ECONNREFUSED` → `CONNECTION_REFUSED`
  - `ECONNRESET` → `CONNECTION_RESET`
  - `ETIMEDOUT` → `TIMEOUT_ERROR`
  - `EPROTO`、`CERT_HAS_EXPIRED`、`UNABLE_TO_VERIFY_LEAF_SIGNATURE` → `TLS_ERROR`
- 新增 HTTP 状态码分类：
  - `401`/`403` → `401`
  - `404` → `NOT_FOUND_ERROR`
  - `408` → `TIMEOUT_ERROR`
  - `429` → `429`
  - 其他 `4xx` → `CLIENT_ERROR`，其他 `5xx` → `SERVER_ERROR`
- 文本回退分类：命中 `401`/`403`、`429`、`timeout`、`DNS`、`connection` 等关键字时返回对应分类；完全无法识别时返回 `UNKNOWN_ERROR` 而非笼统的 `NETWORK_ERROR`。
- 防护：B 站业务码（如 `14012`、`-352`）不会被误判为 HTTP 状态码。
- `friendlyMessage` 为新增分类补充差异化文案，用户可从文案判断应检查网络、API Key、Base URL 还是模型名。

### `Main/src/background/stream.ts`

- 8 处 `inferErrorCode(message)` 调用点全部迁移为 `inferErrorCode(err)`，传入原始错误对象：
  - `handleChatMessage` 的 `tool-error`、`error` 事件与 catch 兜底
  - `handleGenerateTitle` 的 catch
  - `handleTestConnection` 的 catch
  - `setupPortListener` 中聊天路由、标题路由、连接测试路由的 catch
- 连接测试路由兜底由透传原始 `message` 改为 `friendlyMessage(code, message)`，保证异常路径与 `handleTestConnection` 内部的文案语义一致。
