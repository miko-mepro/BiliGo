# 阶段1 致命问题修复

## 阶段目标

消除已确认的渲染崩溃入口。本阶段聚焦唯一一个 CRITICAL 级别问题：R-1 历史标题类型校验缺失。该问题已由静态代码证据确认可在渲染阶段直接抛出 `TypeError`，导致界面崩溃，必须优先于常规体验优化完成。

## 包含方案

### R-1 历史标题类型校验缺失导致搜索渲染抛错

- 严重程度：CRITICAL
- 问题档案：`docs/问题档案/02-状态管理与数据生命周期/R-1-历史标题类型校验缺失.md`
- 涉及代码：
  - `Main/src/components/HistoryDropdown.tsx:214-219`（搜索过滤时调用 `r.title.toLowerCase()`）
  - `Main/src/lib/history/store.ts:59-65`（读取 `bili-agent-history-index` 时强制转换为 `ConversationRecord[]`）
  - `Main/src/lib/history/sync.ts:52-56`（跨标签页同步时只判断是否为数组）
  - `Main/src/content/error-boundary.tsx`（捕获 render 异常）
- 修复目标：在历史记录数据入口建立统一的结构完整性校验层，对从存储和跨标签页同步进入状态的数据逐条校验 `id`、`title` 和时间字段，拒绝非字符串 `title` 等异常数据，使搜索框输入非空字符不再触发 `TypeError`。
- 修改范围：数据入口校验层、错误边界可读提示。
- 测试策略：单元测试覆盖 `title` 为 `null`、数字、对象等异常类型时的拒绝路径；E2E 冒烟验证渲染不再抛错（依赖阶段0）。
- 验收标准：非字符串 `title` 不再进入状态，错误边界能给出可读提示，单元测试覆盖拒绝路径。
- 运行时验证：依赖阶段0 恢复 E2E 后，补充一次渲染冒烟验证。

## 前置依赖

无硬依赖。R-1 的根因已由静态代码证据完全确认，不依赖运行时证据即可完成代码层面修复。

与阶段0 的关系遵循阶段0 的特殊规则：

- E2E 挂载阻塞**不阻塞** R-1 的静态修复（代码实现和单元测试）。
- E2E 挂载阻塞**阻塞** R-1 的最终运行时证据采集（E2E 冒烟验证渲染不再抛错）。

因此，R-1 可在阶段0 同步推进，但其 `completed` 状态的最终验收需要阶段0 提供运行时证据支持。在阶段0 完成前，R-1 可标记为 `needs_review`。

## 可并行项

- 与阶段0 的 E2E 阻塞排查和运行时证据采集通道搭建并行。
- 与阶段2 中可由静态证据确认的问题（N-2、S-3 设计、S-2 设计）并行。
- 本阶段只包含一个问题，内部无并行需求。

## 阶段退出条件

- R-1 的历史记录数据入口校验已实现，非字符串 `title` 不再触发 `r.title.toLowerCase()` 抛出 `TypeError`。
- `store.ts` 和 `sync.ts` 的读取路径均经过结构完整性检查。
- 错误边界能捕获校验拒绝的异常数据并给出可读提示。
- 代码审查通过，单元测试覆盖非字符串 `title` 的拒绝路径。
- 运行时验证通道可用后，补充一次 E2E 冒烟验证渲染不再抛错（本条件可在阶段0 完成后补验，不阻塞本阶段代码层面的 `needs_review`）。

## 风险

- **校验层可能影响历史记录读写性能**：逐条校验 `id`、`title` 和时间字段在大量历史记录场景下可能增加读取延迟。建议校验在数据入口同步完成，但拒绝策略采用跳过异常条目而非中断整批加载。
- **跨标签页同步与主读取路径校验不一致**：`store.ts` 和 `sync.ts` 是两条独立的数据入口，若只修一条会导致跨标签页同步仍可能引入异常数据。修复时两条路径必须同步接入校验层。
- **错误边界提示文案未明确**：R-1 原始文档未明确错误边界应显示的文案。修复前需确认产品期望的提示形式（静默跳过异常条目 vs 显式提示用户数据损坏）。
- **运行时冒烟验证依赖阶段0**：R-1 的 E2E 冒烟验证需要 content script 挂载能力，若阶段0 进度滞后，R-1 的最终验收会延迟。建议在阶段0 完成前先用单元测试覆盖核心路径，运行时补验留待阶段0 完成后。
