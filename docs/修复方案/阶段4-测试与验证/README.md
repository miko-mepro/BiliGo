# 阶段4 测试与验证

## 阶段目标

补齐回归验证、E2E 场景回归和跨域集成验证。本阶段不修复具体问题编号，而是把阶段1 到阶段3 的修复放到完整的测试与验证体系中收口，确保修复在运行时层面成立，并验证待验证假设清单中的高风险假设。

## 包含工作

本阶段包含三类工作：测试覆盖缺口补齐、E2E 场景回归、跨域集成验证。

### 工作二：E2E 场景回归

对应问题档案：`docs/问题档案/05-测试与验证缺口/E2E运行阻塞问题.md`

在阶段0 恢复 E2E 能力后，对阶段1 到阶段3 的修复进行 E2E 场景回归。回归场景按问题域组织：

| 场景类别 | 覆盖问题 | 回归要求 | 依赖阶段 |
| --- | --- | --- | --- |
| 渲染崩溃回归 | R-1、R-2、R-3 | 历史记录含异常 `title` 时搜索不再抛错；历史重命名视图切换后不再写入过期状态；连接测试视图切换后不再写入过期状态 | 阶段0 + 阶段1 + 阶段3 |
| 自动滚动回归 | S-2 | 流式输出期间用户上拉后不再自动滚动；新消息到达且用户在底部时恢复滚动 | 阶段0 + 阶段2 |
| 批次保留回归 | S-3 | 两次搜索的结果按批次保留，旧视频挂在旧输出下，旧 insight 与旧视频归属一致 | 阶段0 + 阶段2 |
| 排序优先级回归 | S-4 | rerank 数组经过 `MessageList` 后最终 DOM 顺序符合产品决策；视频数组更新后用户手动选择保留或重置符合预期 | 阶段0 + 阶段2 |
| 辅助内容时机回归 | S-1 | 搜索过程中 UI 区域不再立即变化，辅助内容在合适时机统一展示 | 阶段0 + 阶段3 |
| 聊天流总超时回归 | N-2 | 上游请求不返回时不长期等待，总超时后中断并给出可读错误 | 阶段0 + 阶段2 |
| 错误分类回归 | N-1、N-4 | 不同根因的网络异常显示不同文案；Bilibili 工具网络失败与连接测试文案语义一致 | 阶段0 + 阶段3 |
| 断线检测回归 | N-3 | 设置 Port 断线时前端及时感知并给出反馈 | 阶段0 + 阶段3 |

E2E 回归要求：

- 每个场景至少覆盖一次目标 smoke 测试，能进入面板打开和按钮交互阶段。
- 渲染崩溃回归需采集浏览器控制台的 render stack、事件处理器异常和 `Maximum call stack size exceeded`（若存在）。
- 自动滚动回归需采集 `scrollIntoView` 调用次数和最终 `scrollTop`。
- 排序优先级回归需采集视频 `bvid` 顺序、播放量顺序和 rerank `items` 顺序。
- 错误分类回归需记录发生时间、Provider 类型、Base URL、模型名、错误文案和耗时，不记录 API Key、Cookie 或完整请求凭据。

### 工作三：跨域集成验证

对应问题档案：`docs/问题档案/问题关联图.md` 中的跨文档关联。

跨域集成验证覆盖问题关联图中记录的四类跨文档关联，确保不同问题域的修复在集成点不产生冲突：

| 集成点 | 关联问题 | 验证要求 | 依赖阶段 |
| --- | --- | --- | --- |
| 网络层错误分类与工具调用集成 | N-1、N-4 | 连接测试和 Bilibili 工具调用面对相似网络异常时显示一致文案，用户能从文案判断根因 | 阶段0 + 阶段3 |
| 状态管理与渲染层集成 | S-3、R-1 | 外部数据进入前端状态时经过结构校验，视频结果按批次归属模型保留，历史记录非字符串 `title` 被拒绝 | 阶段0 + 阶段1 + 阶段2 |
| TestConnectionButton 状态管理集成 | N-3、R-3 | 设置 Port 断线检测和连接测试 Promise 取消在共用代码上不冲突，listener、timer、取消和过期结果统一检查 | 阶段0 + 阶段3 |
| 搜索展示因果链集成 | S-1、S-2、S-3、S-4 | 从 S-1 推送时机到 S-4 排序覆盖的完整链路在修复后行为一致，因果链逐级传导不再放大 | 阶段0 + 阶段2 + 阶段3 |
| 数据生命周期一致性集成 | S-3、insight 追加策略 | 视频数组和 insight 卡片的数据生命周期一致，旧视频与旧 insight 归属一致 | 阶段0 + 阶段2 |

跨域集成验证要求：

- 每个集成点至少覆盖一次跨问题域的端到端测试，验证不同修复在集成点不产生冲突。
- TestConnectionButton 状态管理集成需统一检查 listener、timer、取消和过期结果，确认 N-3 和 R-3 的修复在共用代码上协调一致。
- 搜索展示因果链集成需验证从 S-1 推送时机到 S-4 排序覆盖的完整链路，确认因果链逐级传导不再放大。

- 采集非敏感信息，不记录 API Key、Cookie 或完整请求凭据。
- 假设被运行时证据确认后，应将其从待验证类移至已确认问题分类，并更新问题档案总索引 README 的统计表。
- 假设不等于根因，不能直接写入修复计划。任何基于假设的修复应先验证对应假设，确认触发场景和实际表现后再设计修复方案。

## 前置依赖

- **强依赖**：阶段0 恢复 E2E 能力。本阶段所有运行时验证、E2E 场景回归和跨域集成验证都依赖阶段0 恢复的 E2E 挂载能力和运行时证据采集通道。
- **建议依赖**：阶段1 到阶段3 的修复基本完成。本阶段的回归验证针对阶段1 到阶段3 的修复，若修复未完成则回归验证无对象。
- **产品决策依赖**：测试覆盖缺口3、4、6、7 需要产品决策后才能定义测试预期行为。建议在阶段2 实施期间同步推进产品需求确认。

## 可并行项

- 测试覆盖缺口1、2、5（纯测试技术问题）可在阶段2 的 S-2、S-4 修复完成后立即补齐，无需等待本阶段其他工作。
- 待验证假设的运行时验证可与 E2E 场景回归并行采集，因为假设验证和场景回归的运行时证据采集通道相同。
- 跨域集成验证需在相关阶段修复完成后进行，不能与修复本身并行。

## 阶段退出条件

- 测试覆盖缺口清单的 7 项缺口均已补齐测试用例，或已明确产品决策后定义预期行为。
- E2E 场景回归覆盖渲染崩溃、自动滚动、批次保留、排序优先级、辅助内容时机、聊天流总超时、错误分类和断线检测。
- 跨域集成验证覆盖网络层错误分类与工具调用、状态管理与渲染层、TestConnectionButton 状态管理、搜索展示因果链、数据生命周期一致性的集成点。
- 运行时验证已采集 N-V1 到 N-V6、S-V1 到 S-V5 假设的最小证据，已确认的假设已从待验证类移至已确认问题分类，并更新问题档案总索引 README 的统计表。
- 所有阶段的运行时补验条件均已达成，阶段1 到阶段3 中标记为 `needs_review` 的问题已转为 `completed`。

## 风险

- **产品决策滞后阻塞测试补齐**：测试覆盖缺口3、4、6、7 需要产品决策后才能定义预期行为。若产品决策滞后，这四项缺口无法在本阶段补齐，阶段4 退出条件无法达成。建议在阶段2 实施期间即启动产品需求确认流程。
- **假设验证可能揭示新根因**：待验证假设被运行时证据确认后，可能揭示与静态分析不同的根因，导致阶段1 到阶段3 的部分修复需要返工。建议假设验证优先于其他运行时验证推进，尽早发现潜在返工点。
- **E2E 场景回归可能受 MV3 service worker 回收影响**：service worker 可能在测试期间被浏览器回收或重启（对应假设 N-V3），导致 E2E 测试不稳定。需评估 service worker 生命周期对测试稳定性的影响。
- **跨域集成验证覆盖面广**：四类跨文档关联涉及多个问题域，集成点可能存在未被原始文档记录的隐式依赖。建议在集成验证前先梳理问题关联图的完整依赖路径，避免遗漏集成点。
- **运行时证据采集可能影响测试行为**：在 service worker 注入日志、在 content script 录制 DOM 可能影响流式输出性能或滚动行为，需验证采集通道本身不改变被验证的行为（与阶段0 的风险一致）。
